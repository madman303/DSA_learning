## 每份讲义的统一结构

所有讲义都按同一套结构写，便于你自学和复习：

1. **本讲导读** —— 在整门课中的位置、可检验的学习目标、前置要求
2. **知识地图** —— 知识点 + 依赖顺序 + 后面哪一讲会用到
3. **逐节精讲** —— 定义、为什么需要、内存/指针示意图、完整可编译的 C 代码、逐行解释、边界情况
4. **复杂度分析** —— 时间/空间，带推导
5. **常见错误与易混点** —— 错误示例 → 正确写法 → 原因
6. **动手练习** —— 分基础/进阶，**每题都有完整参考答案**
7. **自测清单** —— 自查问题（附答案要点）
8. **课件页码对照表** —— 知识点 ↔ PDF 页码，可一秒回到原 PPT

## ⚠️ 关于 `code/` 里的代码：**先自己写，再看**

课件原话：**"把它逐行抄成自己的实现等于没做题。"**（L03 第 88 页）

所以本仓库的代码分成两类，用法完全不同：

| 目录 | 性质 | 怎么用 |
|---|---|---|
| `code/l01/` | **示范代码** | 像读教材例题一样读，但读完要**默写**一遍 |
| `code/cproject/list.c`、`sort.c` | **参考答案（答案册）** | ⛔ **不要先读**。先自己把 `list.c`/`sort.c` 写出来，卡住再看 |
| `code/cproject/test/` | **验收器（给你用的）** | ✅ 这是你应该主动用的：写完自己的实现，`bash test/run_tests.sh` 全绿才算过 |
| `code/cproject/list.h`、`sort.h` | **接口约定** | ✅ 应该读：它规定了你必须实现哪些函数、参数与返回值是什么 |

**练法（推荐）**：

```sh
cp -r code/cproject ~/my-list        # 复制一份到工作区，别在原目录改
cd ~/my-list
: > list.c ; : > sort.c              # 把两个实现文件清空（答案留在原目录里）
# 只照着 list.h / sort.h 的接口注释，自己把每个函数写出来
bash test/run_tests.sh               # 用测试套件验收，全绿才算过
```

测试会告诉你"期望值 vs 实际值"，但不会告诉你算法怎么写——这才是正确的练习方式。

## 快速开始（30 秒）

```sh
# 第 1 讲配套代码：编译、运行、内存检查
cd code/l01
make            # 零警告零错误
make run        # 看 7 个程序的真实输出
make asan       # AddressSanitizer 检查内存问题
make O0         # 对比 -O0 与 -O2，看编译器把代码优化没了

# 第 3、4 讲配套 C 工程：链表 + 排序 + 单元测试
cd ../cproject
make && make run
bash test/run_tests.sh
```

## 学这门课的正确姿势

1. **先读路线图**，再按单元顺序学，不要跳。
2. **只看不动笔 = 没学**。每读一段指针操作，先在纸上画内存图。
3. **默写胜过阅读**。合上讲义从空白文件写起，卡住再看，然后重新从空白写。
4. **默认打开内存检查**：`gcc -g -fsanitize=address,undefined`。让工具替你抓 bug。
5. **报性能数字必须交代清楚**：机器、编译器与优化级别、输入规模、测量次数、取值方式。
6. **作业按时提交**：默认下周三 23:59 截止；push 前先 `git pull`；用课程 Git 平台 <https://git2.taohonker.space>。
7. **上机考试闭卷断网、只有一次机会**，所以平时就要练到"闭眼能写"。

## 关于 `extracted/` 与 `tools/pdftext.py`

原始课件是 PDF，无法直接检索。仓库里已经把 12 份 PDF 全部提取为纯文本，保留 `===== PAGE n =====` 分页标记，所以你可以用 `grep` 在整门课里搜索任意概念：

```sh
grep -rn "哨兵" extracted/          # 看看"哨兵"在哪些讲里出现过
grep -rn "realloc" extracted/       # 追踪一个知识点的全部出现位置
```

> **提取质量说明**：`*-slides.txt` 是**完整正文**（经逐条比对，讲义版的内容全部包含在其中），阅读时以它为准；`*-unified.txt` 因为 PDF 把正文放在 Form XObject 里，只能提取出**目录与页码**，所以它的用处是**查章节编号和页码**。

`tools/pdftext.py` 是提取器本身（纯 Python，无第三方依赖，支持 FlateDecode 与 ToUnicode CMap）。课件更新后可以重新提取：

```sh
python3 tools/pdftext.py courseware/l01-introduction/l01-introduction-slides.pdf > extracted/l01.txt
```
