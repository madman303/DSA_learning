## 1. Git：只需要掌握这些

### 1.1 四个区域（记住这张图，Git 就不会乱）

```
工作区                暂存区              本地版本库           远程仓库
(你编辑的文件)  --add-->  (待提交清单) --commit--> (提交历史) --push--> (fork)
     ^                                                              |
     +---------------------- pull / fetch --------------------------+
```

- **工作区**：你看到的文件。
- **暂存区（index）**：`git add` 后进入的"下次提交要包含什么"的清单。
- **本地版本库**：`git commit` 后形成的不可变提交历史，每个提交有唯一哈希 ID。
- **远程仓库**：你在 <https://git2.taohonker.space> 上的 **fork**。

**一句话理解 commit**：提交 = 给当前被暂存的内容拍一张快照 + 记录作者、时间、说明 + 指向前一个提交。历史是一条链，`HEAD` 是你现在站在哪。

### 1.2 必背的 12 条命令

```sh
# ── 一次性配置 ──────────────────────────────
git config --global user.name  "你的名字"
git config --global user.email "你的邮箱"

# ── 拿到仓库 ────────────────────────────────
git clone <你的 fork 地址>
git remote -v                        # 看清推到哪里（排查"推错地方"）

# ── 日常循环（99% 的时间就用这四条）────────
git status                           # 现在有哪些改动？★ 最常用
git add <文件>   /   git add .        # 放进暂存区
git commit -m "说明这次做了什么"       # 提交；说明写清楚，它本身就是作业的一部分
git push                             # 推到你的 fork

# ── 交作业前的保命动作 ─────────────────────
git pull --rebase                    # ★ 先同步再推，避免冲突被判 D
git log --oneline --graph            # 看历史（提交记录是作业的一部分）

# ── 撤销 ───────────────────────────────────
git restore --staged <文件>           # 撤销暂存（改动还在）
git restore <文件>                    # 丢弃工作区改动（★ 不可恢复）
```

### 1.3 三种常见事故的正确处理

| 场景 | 做法 |
|---|---|
| `push` 被拒（`rejected / non-fast-forward`） | 远程有你本地没有的提交。**正确**：`git pull --rebase` 解决冲突后再 `git push`。**绝不** `git push --force`（会抹掉别人的提交） |
| **冲突（conflict）** | ① `git status` 看哪些文件冲突；② 打开文件，会看到 `<<<<<<<`、`=======`、`>>>>>>>` 三段标记；③ 人工编辑成最终想要的样子，**并删掉这三行标记本身**；④ `git add <文件>`（这一步就是"标记为已解决"）；⑤ `git commit` 完成合并 |
| 提交信息写错 / 漏了文件（且还没 push） | `git commit --amend`（会换提交 ID，只对**未推送**的提交用） |

> **课件第 15 页问题**：冲突一般是什么原因？怎么解决？→ 别背概念，**在你的仓库里真的制造一次冲突并解决它**，把过程写进报告。这是实验的精髓。

### 1.4 实验必须照做的五步（课件 12–15 页）

1. **创建和克隆仓库**：在课程平台 fork 教师仓库（**仓库名不改**）→ `git clone` 你的 fork。
2. **提交更改**：改文件 → `git status` → `git add` → `git commit -m "..."` → `git push`。
3. **查看状态和历史**：至少提交 3 次，用 `git log --oneline --graph` 证明历史完整。
4. **分支管理**：`git branch` / `git switch -c <新分支>` / 修改 / 提交 / 合并回主线；再故意制造一次冲突并解决。
5. **远程操作**：`git remote -v`、`git fetch`、`git pull`、`git push` 各跑一遍并记录输出。

## 2. 指针实验：课件的问题清单（**答案自己写**）

对每个问题给出：**结论 + 代码验证 + 内存图 + 真实输出**。下面只给思考方向和验收方式。

| # | 课件问题 | 思考方向 | 怎么验证 |
|---|---|---|---|
| 1 | **指针变量可以指向自身吗？如果可以，如何定义和初始化？** | 指针类型要与"被指对象的类型"匹配。让 `p` 指向 `p` 自己时类型不匹配 → 课件给了三条方案：`void *`、`uintptr_t`、函数指针 | 写出能编译的最简版本；打印 `&p` 与 `(void *)p` 看是否相等；比较 `void *v = &v;`（合法）与 `int *p = (int *)&p;`（能编译，但要解释风险） |
| 2 | **指针的值是什么？** | 值是地址；地址是数值，但**打印必须转 `(void *)` 且用 `%p`** | `printf("%p %p %p\n", (void *)&x, (void *)p, (void *)&p)`，解释这三个地址的关系 |
| 3 | **指针、数组、指针数组** | 数组名退化为指向首元素的指针；"指针数组"是"元素为指针的数组" | 写 `int a[3]`、`int *pa[3]`、`int (*ap)[3]` 三种声明，用 `sizeof` 打印区分它们 |
| 4 | **如何改变指针的值？有几种方法？对指针原值加整数偏移的后果？** | ① 重新赋值为另一对象地址；② 指针算术 `p + n`（步长 `sizeof(*p)`）；③ 通过 `int **` 在函数里改。**偏移的后果**：只在同一数组内合法，越界是未定义行为 | 写函数 `void advance(int **p, size_t n)`；再写越界版本，用 `-fsanitize=address` 看它怎么报错 |
| 5 | **数组在内存中的存在形式？数组与指针的关系？** | 连续内存；三处不等价（`sizeof`、`&arr`、能否赋值） | 打印 `&a[i]` 之间的字节差；打印 `sizeof(a)` 与 `sizeof(&a)` |
| 6 | **Python 里有没有指针？有没有替代品？如何使用？** | Python 变量都是"名字绑定到对象"，不暴露地址；替代品是**引用 + 可变对象**；`id()` 可看对象身份 | 写代码证明 `b = a`（list）后改 `a` 会改到 `b`；再证明 `str` 不会 |

## 3. 计时：方法、陷阱、要交的数据

### 3.1 两种时钟（选错就白测）

| 时钟 | 代码 | 测什么 | 什么时候用 |
|---|---|---|---|
| CPU 时间 | `clock()` 除以 `CLOCKS_PER_SEC` | 进程真正占 CPU 的时间（不含等待） | 纯计算型代码 |
| 墙钟时间 | `clock_gettime(CLOCK_MONOTONIC, &t)` | 真实流逝时间（单调，不受时钟调整影响） | 用户感知的响应时间 |

Python：`time.perf_counter()`（单次）、`timeit.repeat(...)`（批量比较）。

### 3.2 四个陷阱（照做就不会翻车）

1. **结果被优化删除**：若被测代码的结果没人使用，`-O2` 会把整个循环删掉，测出 0 秒。→ 把结果写入 `volatile` 变量或打印出来，并**在报告里写明编译选项**。
2. **只测一次**：第一次运行含缓存冷启动。→ 重复 5 次以上，**取最小值**。
3. **分辨率不够**：`clock()` 分辨率约 1 µs，测 10 ns 的代码只会得到 0。→ 放进循环跑 10⁶ 次再除以次数。
4. **不校验结果**：计时循环里算错了，再快也没意义。→ 累加校验和并在最后打印。

### 3.3 实验要交的数据

- **常见操作符**：`i++`、`i += 1`、`i * 2`、整数除法、取模、浮点乘法、函数调用、数组读写、指针解引用 —— 各测单次耗时（用循环放大）。
- **简单函数**：Fibonacci 递归版与迭代版，取 `n = 20, 25, 30, 35, 40` 列表。
- **至少两种语言**（C 与 Python）。
- 每个数字注明：机器、编译器/Python 版本、优化级别、重复次数、取值方式。

> **你要自己回答的分析题**：迭代版耗时随 n 怎么变？递归版呢？把递归版相邻两行的耗时相除得到什么数？它和 φ 是什么关系？
