## 3. 为什么这门课重要：两个案例（课件 8–15 页）

### 3.1 案例一：校园路径规划

**问题**：从朗溪街 10 号门走到图书馆，怎么走最快？

**抽象过程（这是本课程最核心的思维动作）**：

| 现实世界 | 数据结构中的概念 |
|---|---|
| 建筑物、路口 | 节点（vertex / node） |
| 道路 | 边（edge） |
| 道路长度、步行时间 | 边的权重（weight） |
| 校园地图 | 图（graph） |
| "怎么走最快" | 单源最短路径问题（Dijkstra / BFS） |

**延伸思考（课件原题）**：如果边的"代价"随天气、拥堵动态变化呢？如果可选步行/自行车/电动车呢？如果体力有限（能量约束）呢？

> 助教解读：动态权重 → 时间依赖图；多交通方式 → 多层图（layered graph）；体力约束 → 资源约束最短路。**同一道题，数据结构选型一变，算法就完全不同。** 这就是"数据结构决定算法"。

**现实应用**：地图导航、物流调度、网络路由。

### 3.2 案例二：人际相似度度量

**背景**：推荐系统的核心问题之一是——如何衡量"两个人之间的距离"？距离越近，推荐相关性越高。

**维度不断扩张的过程**：

1. 空间位置（地理坐标）→ 2 维
2. 籍贯、性别 → 类别型特征
3. 口味、社会单位、兴趣爱好 → 多维度
4. 政治信念、价值观 → 难以量化的深层次特征

**问题随之变难**：

- 每加一个特征维度，就变成**高维空间中的距离计算**；
- 不同类型的数据（数值型/分类型/集合型/文本型）需要**不同的数据结构**；
- 需要设计合适的**距离函数**：欧氏距离、曼哈顿距离、余弦相似度、Jaccard 相似系数。

**数据结构在这里的作用**：用**结构体**（C 的 `struct`、Python 的 `class`、Julia 的 `struct`）把一个人的多维特征打包成一个类型，再写函数计算两人距离。

本讲作业 1 就是它的最小雏形：用 `struct` 表示学生。

### 3.3 课程核心观点（课件第 15 页）

> 现实问题往往复杂多变，**解决问题的能力，根本在于对数据的高效组织（数据结构）和高效处理（算法）**。
> 数据结构决定数据的**存储方式与访问效率**；算法决定数据处理的**速度与资源消耗**。

## 4. 三种语言的内存观（课件 16–22 页）

这一节的目标不是让你精通三种语言，而是让你**看清"抽象层次"这件事**：同一件事（共享一份数据），三种语言用三种机制实现，代价与风险各不相同。

### 4.1 C 语言：直接内存抽象

C 把内存直接交给程序员：

- **指针**：存储地址的变量，用 `&` 取地址、`*` 解引用，可以**做算术运算**；
- **数组**：一块连续内存，元素类型相同；数组名在多数场合**退化为指向首元素的指针**，但数组与指针**并不等价**（`sizeof`、`&arr`、能否赋值都不同）；
- **结构体**：把不同类型的数据聚合，每个成员有**固定偏移量**。

> **C 的代价**：内存泄漏、野指针、缓冲区溢出非常常见，必须程序员自己负责。
> 这三类错误在 Java/Python 里基本不会出现——因为语言替你管了。**课程的取舍是：先学会自己管，才谈得上理解"自动管理"到底做了什么。**

### 4.2 Julia：性能与抽象的双赢

- **类型系统**：可对变量、函数参数、返回值做类型注解；注解帮助 JIT 优化，提升运行效率。
- **数组**：可变的、类型化的、**连续**内存块，底层与 C 类似；支持多维数组，**索引从 1 开始**。
- **结构体**：`struct` 定义**不可变**类型，`mutable struct` 定义**可变**类型。
  - 不可变类型适合做数据快照、哈希表键；
  - 可变类型适合需要频繁修改的场景。
- **内存与性能**：类型推断 + JIT，性能接近 C，同时保留高级语言的易用性。

### 4.3 引用与指针：相同点与区别（课件第 21 页）

**相同点**

- 都是"间接访问"数据的机制：不直接存数据本身，而是指向/引用数据在内存中的位置；
- 都允许多个变量指向同一份数据，实现**数据共享**。

**区别**

| 对比项 | C 指针 | 引用（Python/Julia/Java） |
|---|---|---|
| 本质 | 内存地址的直接操作 | 更高级的抽象，不允许直接操作地址 |
| 算术 | 支持 `p+1`（步长 = `sizeof(*p)`） | 不支持 |
| 指向 | 可指向任意类型，可指向指针本身（多级） | 通常不能 |
| 可变性 | 指针变量本身可重新赋值 | Python/Julia 变量可重新绑定；C++ 引用不可改绑 |
| 内存管理 | **手动** `malloc/free` | 通常**垃圾回收**自动管理 |

**Python 的两条规则（必须记牢）**

```python
# 规则 1：不可变对象（int/float/str/tuple）——变量"重新赋值"是换指向新对象，原对象不变
a = 10
b = a
a = 20
print(a, b)          # 20 10   ← b 仍指向 10

# 规则 2：可变对象（list/dict/set）——多个变量指向同一对象，改一个全都变
arr1 = [1, 2, 3]
arr2 = arr1          # 这里没有拷贝！arr2 和 arr1 是同一个列表的两个名字
arr1.append(4)
print(arr2)          # [1, 2, 3, 4]
arr2.append(5)
print(arr1)          # [1, 2, 3, 4, 5]
```

Julia 同理：Julia 变量本质上是"绑定"到对象的引用；不可变对象赋值不影响原对象，可变对象的修改影响所有引用。

### 4.4 AI 互动环节（课件给的两个提问任务）

课件明确鼓励用 AI 辅助学习，还留了两个提问任务。给你**参考答案要点**，方便你检验 AI 有没有胡说：

**提问任务 1**："Python 中的变量到底是值传递还是引用传递？请用可变和不可变对象为例详细解释。"

> **答案要点**：严格说是"**按对象引用传递**"（pass by object reference / call by sharing），两种说法都不完全准确。
> 函数收到的是**实参对象的引用副本**。若在函数内对**可变对象**做原地修改（`lst.append`），调用方可见；若对**参数名重新赋值**（`lst = [9]`），只是改了函数内局部名字的绑定，调用方看不到。
> 对**不可变对象**（`int`、`str`、`tuple`），任何"修改"都会新建对象并重新绑定，因此调用方永远看不到变化。
> 判据不是"可变/不可变"，而是"你是**原地修改对象**还是**重新绑定名字**"。

```python
def f(xs, n):
    xs.append(99)   # 原地修改 -> 调用方可见
    n = n + 1       # 重新绑定局部名字 -> 调用方看不到

a = [1, 2]
b = 5
f(a, b)
print(a, b)         # [1, 2, 99] 5
```

## 6. 代码计时：科学测量的方法论（课件 23–29 页）

### 6.1 为什么要计时

- 算法与程序的效率直接影响应用的可行性与用户体验；
- 直观的"快/慢"感受**往往不准确**；
- 通过计时可以比较不同算法、不同实现方式的优劣，指导后续优化。

### 6.2 三种语言的计时工具

**C：`clock()` 测 CPU 时间**

```c
#include <stdio.h>
#include <time.h>

int main(void) {
    clock_t start = clock();

    /* ---- 需要计时的代码 ---- */
    volatile long long sum = 0;
    for (long long i = 0; i < 1000000; i++) sum += i;
    /* ----------------------- */

    clock_t end = clock();
    double cpu_time_used = (double)(end - start) / (double)CLOCKS_PER_SEC;
    printf("运行时间: %f 秒\n", cpu_time_used);
    return 0;
}
```

`clock()` 返回的是**进程消耗的 CPU 时间**（不含等待 I/O、被调度出去的时间），受调度影响较小，适合计时**纯计算型**代码。

**C：`clock_gettime()` 测墙钟时间（真实流逝时间）**

```c
#define _POSIX_C_SOURCE 199309L
#include <time.h>

struct timespec t0, t1;
clock_gettime(CLOCK_MONOTONIC, &t0);
/* 被测代码 */
clock_gettime(CLOCK_MONOTONIC, &t1);
double wall = (double)(t1.tv_sec - t0.tv_sec)
            + (double)(t1.tv_nsec - t0.tv_nsec) / 1e9;
```

- `CLOCK_MONOTONIC`：单调递增，**不受系统时钟调整影响**，测耗时首选；
- 不要用 `CLOCK_REALTIME` 测耗时（可能被 NTP 校正回拨）。

**C++：`<chrono>`（课件 26 页）**

```cpp
#include <iostream>
#include <chrono>
int main() {
    auto start = std::chrono::high_resolution_clock::now();
    volatile long long sum = 0;
    for (int i = 0; i < 1000000; ++i) sum += i;
    auto end = std::chrono::high_resolution_clock::now();
    auto duration = std::chrono::duration_cast<std::chrono::microseconds>(end - start);
    std::cout << "运行时间: " << duration.count() << " 微秒" << std::endl;
    return 0;
}
```

支持秒/毫秒/微秒/纳秒，跨平台，推荐用于 C++ 性能分析与竞赛编程。

**Python：`time.perf_counter()` 与 `timeit`**

```python
import time, timeit

t0 = time.perf_counter()      # 单调、高精度，测耗时首选
# 被测代码
t1 = time.perf_counter()
print(f"{(t1 - t0) * 1e6:.2f} 微秒")

# 更严格：自动多次运行、取最小值、可关闭 GC 干扰
best = min(timeit.repeat("fib_iter(34)", globals=globals(), number=100_000, repeat=5))
print(f"单次 {(best / 100_000) * 1e9:.0f} 纳秒")
```

**Julia：`@time` vs `@btime`（课件 28 页）**

```julia
A = [1, 2, 3]
@time sum(A)                    # 只运行一次，易受 JIT 编译与全局变量影响

using BenchmarkTools
@btime sum($A)                  # 多次运行、$ 避免全局变量干扰、报告最优耗时与内存分配
```

### 6.3 关键总结（课件第 29 页）

- 计时工具的选择要结合语言特性与实际需求；
- C 需手动计时，适合底层性能分析；
- Python 的 `timeit` 和 Julia 的 `@btime` 能自动多次测试，结果更可靠；
- Julia 的 `@btime` 还能显示内存分配，有助于发现隐藏瓶颈；
- 更深入的运行时分析要借助 Profiler：`gprof`、`valgrind`、`perf` 等。

### 6.4 计时的五个陷阱（**这一节是助教补充，课件只给了工具，没讲陷阱**）

#### 陷阱 1：编译器把你"要计时"的代码删了

如果被测代码的结果**没有任何可观测的用途**，编译器有权整个删掉它。这不是 bug，是优化。

我们实测（`code/l01/06_optimization_trap.c`，2 亿次线性同余递推）：

```
--- -O0 ---                     --- -O2 ---
unused_loop : 0.194443 秒        unused_loop : 0.000000 秒   ← 整个循环被删除
used_loop   : 0.194607 秒        used_loop   : 0.192040 秒
```

**对策**：让结果"被使用"——写入 `volatile` 变量、打印、或汇合到返回值；做对照实验时**报告编译选项**。

#### 陷阱 2：一次测量不可信

- 第一次运行包含**缓存冷启动、页错误、JIT 编译**开销；
- 应当**重复多次，取最小值**（最小值最接近"算法本身的代价"，最大值反映最坏干扰）。

#### 陷阱 3：时钟分辨率不够

`clock()` 在本机 `CLOCKS_PER_SEC = 1000000`，即分辨率 1 微秒。测一个 7 纳秒的 `fib_iter(34)`，单次读数必然是 0。**对策**：把被测代码放进循环跑很多次，再除以次数（本讲 `05_timing_fib.c` 用 100 万次测 `fib_iter(34)`，得 7.3 ns/次）。

#### 陷阱 4：混淆 CPU 时间与墙钟时间

- CPU 时间 < 墙钟时间：程序在等 I/O、等锁、被换出；
- CPU 时间 > 墙钟时间：多线程并行。

**测量目标不同，工具就不同**：测算法计算量用 `clock()`；测用户感知的响应时间用 `clock_gettime(CLOCK_MONOTONIC)`。

#### 陷阱 5：测完不复核结果的正确性

计时循环里如果结果算错，速度快也毫无意义。**正确做法**：在计时循环里累加校验和并在最后打印（本讲代码就打印了 `acc` / `acc2`）。

### 7.2 变量、类型、`sizeof`

```c
int    a = 42;          /* 通常 4 字节 */
char   c = 'A';         /* 1 字节，本质是小整数 */
double d = 3.14159;     /* 8 字节，IEEE 754 双精度 */
unsigned long long big = 18446744073709551615ULL;  /* 8 字节，最大整数类型之一 */

printf("sizeof(int)=%zu sizeof(char)=%zu sizeof(double)=%zu sizeof(void*)=%zu\n",
       sizeof(int), sizeof(char), sizeof(double), sizeof(void *));
```

**`sizeof` 是编译期运算符，不是函数**，返回 `size_t`（用 `%zu` 打印）。

**C 没有字符串类型**：字符串是"以 `'\0'` 结尾的字符数组"。

```c
char s1[] = "abc";       /* 4 字节：'a','b','c','\0' —— 可修改 */
char *s2  = "abc";       /* 指针指向只读字面量 —— 试图 s2[0]='x' 是未定义行为 */
char s3[8] = "abc";      /* 8 字节，末尾自动补 0 */
printf("%zu %zu %zu\n", sizeof s1, sizeof s2, sizeof s3);   /* 4 8 8 */
```

**作用域与存储期**（后面讲链表节点生命周期要用）：

| 存储类 | 存放位置 | 生命周期 | 默认初值 |
|---|---|---|---|
| `auto`（局部变量） | 栈 | 进入作用域到离开 | **未定义（垃圾值）** |
| `static`（局部） | 数据区 | 整个程序运行期 | 0 |
| `static`/全局 | 数据区 | 整个程序运行期 | 0 |
| `malloc` 出来的 | 堆 | 从 `malloc` 到 `free` | **未定义（脏数据）** |

> 关键区别：**栈对象在函数返回时自动销毁；堆对象只有 `free` 才销毁。** 链表节点的 `next` 指针指向的必须是堆对象，否则函数一返回指针就悬空了。

### 7.3 指针：本课程最重要的工具

#### 7.3.1 什么是指针

**指针是一种特殊的变量：它存储的不是数据本身，而是一个内存地址。**

```
        内存（地址 → 内容）
        ┌──────────┬────────┐
        │ 0x1000   │  10    │  ← int x = 10;      （4 字节）
        ├──────────┼────────┤
        │ 0x1004   │ 0x1000 │  ← int *p = &x;     （8 字节，内容是 x 的地址）
        └──────────┴────────┘
```

指针有**双重性**：

- 它既是**一个值**（地址，如 `0x1000`）——可以打印、可以比较、可以做算术；
- 也是对另一对象的**引用**——`*p` 就是这个对象本身。

**两条容易被忽略的事实**：

1. **指针 p 自己也占据内存**，所以 `&p` 是合法的（得到"指向指针的指针"）；
2. **指针的步长由所指类型决定**：`p + 1` 前进 `sizeof(*p)` 字节；而**指针自身的大小由平台决定**（64 位平台 8 字节），与所指类型无关。

实测（`01_pointer_basics.c`）：

```
sizeof(int)   = 4 字节
sizeof(int *) = 8 字节（64 位平台上与所指类型无关）
arr       = 0x7ffeaed7e680
arr + 1   = 0x7ffeaed7e684
字节差    = 4  (等于 sizeof(int))
```

#### 7.3.2 lvalue 与 rvalue（理解 `*p` 的关键）

- **lvalue（左值）**：表示一个**可寻址的内存位置**，有地址，可出现在赋值号左边；
- **rvalue（右值）**：表示一个**具体的数值或临时结果**，没有固定地址，只能参与计算。

```c
int x = 5;
int *p = &x;
*p = 20;            /* *p 作左值：修改 x 所在的内存 */
int y = *p + 1;     /* *p 作右值：读出 x 的值参与运算 */
```

**为什么这很重要**：`*p` 是左值还是右值，取决于它出现在赋值号哪一侧。如果 `p` 指向无效地址（未初始化或已悬空），那么 `*p` **无论作左值还是右值都会崩溃**。

#### 7.3.3 声明与初始化

```c
int *p;              /* 指向 int 的指针（未初始化！里面是随机地址） */
```

**读法**：从变量名往右读——`int *p` 读作"p 是一个指针，指向 int"。

**三种初始化方式**：

```c
int x = 10;
int *p1 = &x;        /* 1. 指向某个变量 */
int *p2 = NULL;      /* 2. 置为 NULL（安全的默认值） */
int *p3;             /* 3. 延迟初始化：先声明，后赋值 —— 但赋值前绝不可解引用 */
p3 = &x;
```

**一个经典陷阱**：

```c
int *a, b;           /* 只有 a 是指针！b 是 int。 */
int *c, *d;          /* c 和 d 才都是指针。 */
```

**安全提醒（课件"小心 1"，三条铁律）**：

1. 务必初始化指针——未初始化的指针里是随机地址，解引用会导致崩溃；
2. `NULL` 是安全的默认值——暂时没有目标时先赋 `NULL`，使用前检查；
3. 不要随意解引用——只有确认指针指向有效地址才用 `*p`。

#### 7.3.4 取地址 `&` 与解引用 `*`

```c
int x = 10;
int *p = &x;            /* &x：x 的地址 */
*p = 20;                /* 通过 p 修改 x */
printf("%d\n", *p);     /* 读取 x */
printf("%p\n", (void *)p);   /* 打印地址：必须 %p 且强制转 void* */
```

> `printf("%p", (void*)p)` 是**定义良好且可移植**的写法。直接传 `int*` 给 `%p` 在部分平台上属于未定义行为。

#### 7.3.5 指针算术与合法边界

```c
p++      /* 向后移动 1 个元素（不是 1 字节！） */
p + n    /* 向后移动 n 个元素 */
p1 - p2  /* 两个指针之间的元素个数，类型 ptrdiff_t */
```

```c
int arr[5] = {10, 20, 30, 40, 50};
int *p = arr;
for (int i = 0; i < 5; i++) {
    printf("%d\n", *(p + i));      /* 等价于 arr[i] */
}
```

**合法性边界（必须记住，否则是未定义行为）**：

- `p1 - p2` **只有在两个指针指向同一个数组（或末端后一位）时才有定义**；
- **指针算术仅在同一数组内合法**，越界是未定义行为；
- 允许计算"末端后一位"`arr + n`，常用于循环结束判断，但**不可解引用**。

```c
int arr[5] = {10, 20, 30, 40, 50};
int *p = arr;
int *end = arr + 5;        /* 末端后一位：合法但不可解引用 */
while (p != end) {
    printf("%d\n", *p);
    p++;
}
```

#### 7.3.6 数组与指针：像，但不等价

| 表达式 | 类型 | 说明 |
|---|---|---|
| `arr` | `int *`（退化） | 指向首元素；`sizeof(arr)` 例外，是**整个数组大小** |
| `&arr` | `int (*)[5]` | 指向**整个数组**的指针；`&arr + 1` 跳过 20 字节 |
| `arr[i]` | `int` | 等价于 `*(arr + i)`（加法可交换，也等价于 `*(i + arr)`，即 `i[arr]`） |
| `arr = p` | 错误 | **数组名不是可修改的左值**，不能赋值 |

```c
int arr[5] = {1,2,3,4,5};
printf("%zu\n", sizeof(arr));       /* 20：整个数组 */
int *p = arr;
printf("%zu\n", sizeof(p));         /* 8：指针 */
printf("%zu\n", sizeof(&arr));      /* 8：数组指针 */
printf("%zu\n", sizeof(arr) / sizeof(arr[0]));   /* 5：数组长度（唯一推荐的写法） */
```

**"数组名退化为指针"的三种例外**：`sizeof(arr)`、`&arr`、以及用字符串字面量初始化字符数组。

#### 7.3.7 特殊指针类型（课件第 42 页）

```c
void *v = malloc(100);      /* 泛型指针：可指向任意类型，malloc 的返回类型 */
int *ip = (int *)v;         /* 必须先转换才能解引用 */

const int *p1;              /* 所指对象只读，指针可重新指向 */
int *const p2 = &x;         /* 指针本身固定，所指对象可修改 */
const int *const p3 = &x;   /* 两者都不可修改 */

int **pp = &p1;             /* 指向指针的指针：多级间接访问，二维数组、动态分配 */
```

**`const` 读法**：从变量名往右读，`const` 修饰它左边的东西（如果左边没有则修饰右边）。

- `const int *p` → "p 是一个指针，指向 const int" → **不能改 `*p`，能改 `p`**；
- `int *const p` → "p 是一个 const 指针，指向 int" → **能改 `*p`，不能改 `p`**。

### 7.4 进程内存布局：栈 vs 堆（课件第 43 页）

```
高地址
  ┌───────────────┐
  │   命令行参数/环境 │
  ├───────────────┤
  │   栈 Stack     │  ← 局部变量、函数调用帧；向低地址增长；自动管理；典型几 MB
  │      ↓         │
  │                │
  │      ↑         │
  │   堆 Heap      │  ← malloc/calloc/realloc 分配；向高地址增长；手动管理
  ├───────────────┤
  │   BSS 段       │  ← 未初始化/零初始化的全局与静态变量
  ├───────────────┤
  │   数据段 Data  │  ← 已初始化的全局与静态变量、字符串字面量
  ├───────────────┤
  │   代码段 Text  │  ← 只读的机器指令
  └───────────────┘
低地址
```

| | 栈 | 堆 |
|---|---|---|
| 管理方式 | 自动（作用域结束即释放） | **手动**（`malloc` / `free`） |
| 容量 | 有限（典型几 MB） | 取决于进程可用内存 |
| 分配速度 | 极快（移动栈指针） | 较慢（需要管理器找块） |
| 适合 | 小而短命的局部对象 | 大对象、**跨作用域存活**的数据、动态结构 |

**为什么需要动态内存（课件第 43 页的四条理由）**：

1. **数据规模不确定**：输入文件大小、网络包数量只有运行时才知道；
2. **生命周期跨越作用域**：函数返回后仍需存活的数据不能用栈变量安全承载；
3. **大对象与灵活结构**：链表、树、图、可扩容容器需要分层分配与按需扩容；
4. **资源统一管理**：显式 `free` 支持确定性释放，避免长尾占用。

> **本课程的关系**：链表节点必须放在**堆**上。因为节点要在"创建它的函数返回之后"继续存活——放栈上就是悬空指针。第 3 讲会反复回到这一点。

### 7.5 动态内存四件套（课件 44–45 页）

#### `malloc(size)`

```c
int n;
if (scanf("%d", &n) != 1 || n <= 0) { fprintf(stderr, "输入错误\n"); return 1; }

int *arr = (int *)malloc((size_t)n * sizeof(int));
if (!arr) {                                  /* 必须判空！ */
    fprintf(stderr, "分配失败\n");
    return 1;
}
for (int i = 0; i < n; i++) arr[i] = i;
free(arr);
arr = NULL;                                  /* 立即置空，杜绝悬空 */
```

- 申请**至多** `size` 字节的原始内存，返回首地址（`void *`）；
- 内容**未初始化**（脏数据），读出未初始化内容属于未定义行为；
- 失败返回 `NULL`。

#### `calloc(n, elem_size)`

```c
int *zeros = (int *)calloc(8, sizeof(int));   /* 8 个 int，全部置 0 */
if (!zeros) { fprintf(stderr, "calloc 失败\n"); return 1; }
free(zeros);
```

为 `n` 个元素分配、**全部置零**。适合需要默认值为 0、避免未初始化不确定性的场景。

> **额外好处**：`calloc` 会检查 `n * elem_size` 是否溢出。

#### `realloc(ptr, new_size)`

- 尝试把 `ptr` 指向的旧内存调整为 `new_size`；
- **可能原地扩展（地址不变），也可能迁移到新块（地址改变，旧块被释放并复制数据）**；
- 成功返回新地址；**失败返回 `NULL` 且原内存不变**。

**安全模式（必须这样写）**：

```c
int *tmp = (int *)realloc(arr, (size_t)new_size);
if (tmp) {
    arr = tmp;          /* 成功才更新原指针 */
} else {
    /* 失败：arr 仍指向旧内存，可继续使用或释放 */
    fprintf(stderr, "realloc 失败\n");
}
```

**反例（会内存泄漏）**：

```c
arr = (int *)realloc(arr, new_size);   /* 失败时返回 NULL 覆盖了 arr，旧内存再也找不到 */
```

#### `free(ptr)`

- 把 `ptr` 指向的动态内存归还给堆管理器；
- **释放后立刻置 `NULL`**：`free(p); p = NULL;`，避免悬空与二次释放；
- **只释放动态分配的起始地址**，不得对中间地址或成员指针随意调用 `free`。

#### 选择指南（课件第 45 页）

| 需求 | 选择 |
|---|---|
| 固定大小的未初始化块 | `malloc` |
| 需要自动清零（安全默认值） | `calloc` |
| 已有数据按需调整容量 | `realloc`，**用临时指针接收返回值** |
| 不再使用的内存 | `free` 并将指针置空 |

### 7.6 动态数组与扩容策略（课件第 46 页）

**数据结构 = 数据 + 操作 + 不变量。** 动态数组把"指针 + 长度 + 容量"三件事封装成一个类型：

```c
typedef struct {
    int *data;      /* 堆上的连续内存块 */
    int size;       /* 当前元素个数（用户视角的"长度"） */
    int capacity;   /* 内存块能容纳的元素个数（实现视角的"容量"） */
} DynamicArray;
```

**不变量（invariant）**：`0 <= size <= capacity`，且 `data` 至少指向 `capacity` 个 `int` 的空间。

```c
/* 保证容量至少为 need；成功返回 1，失败返回 0（失败时旧内存原样保留） */
static int ensure_capacity(DynamicArray *da, int need) {
    if (need <= da->capacity) return 1;

    int newcap = da->capacity ? da->capacity : 2;
    while (newcap < need) newcap *= 2;          /* 指数增长：容量翻倍 */

    int *tmp = (int *)realloc(da->data, (size_t)newcap * sizeof(int));
    if (!tmp) return 0;                         /* 关键：不要直接写 da->data = realloc(...) */

    da->data = tmp;
    da->capacity = newcap;
    return 1;
}

static int push_back(DynamicArray *da, int v) {
    if (!ensure_capacity(da, da->size + 1)) return 0;
    da->data[da->size++] = v;
    return 1;
}
```

#### 为什么必须"翻倍"而不是"每次加 1"？——均摊分析

**每次加 1 的扩容**：插入第 k 个元素时要搬 k 个元素，总搬运量

$$\sum_{k=1}^{n} k = \frac{n(n+1)}{2} = O(n^2)$$

均摊到每次插入是 $O(n)$。

**翻倍扩容**：容量序列为 $1, 2, 4, 8, \dots, 2^{\lceil \log_2 n \rceil}$，总搬运量

$$\sum_{i=0}^{\lceil \log_2 n \rceil} 2^i < 2n = O(n)$$

均摊到每次插入是 $O(1)$。

**实测验证**（`03_dynamic_array.c`，n = 1,000,000）：

```
实际 realloc 次数      = 20      (约 log2(n) = 20 量级)
累计搬运元素总数        = 1048574 (约 2n)
平均每次 push_back 搬运 = 1.049 个元素 -> 均摊 O(1)
最终 capacity = 1048576
```

**工程注意**：乘以 1.5 倍（如 C++ `std::vector` 的常见实现）比 2 倍更省内存（2 倍可能永远无法复用已释放的旧块），但 2 倍分析的均摊界最干净。两者都是 $O(1)$ 均摊。

### 7.7 结构体（课件 47–51 页）

#### 7.7.1 定义与使用

```c
struct Student {
    int id;
    char *name;
    float score;
};

struct Student s;              /* 栈上的结构体 */
struct Student *p = &s;        /* 指向结构体的指针 */

p->id = 202501;                /* 语法糖：等价于 (*p).id = 202501; */
p->score = 95.5f;
printf("%d\n", s.id);          /* 直接用 . 访问 */
```

`->` 就是 `(*p).成员` 的简写，避免 `(*p).x` 的括号嵌套。

#### 7.7.2 为什么常用结构体指针而不是实例

1. **函数参数传递**：直接传结构体会**复制整个结构体**，开销大；传指针只复制 8 字节，且能让函数**修改调用者的内容**。
2. **动态内存管理**：结构体可能很大或数量不确定，在堆上动态分配更灵活。
3. **数据结构设计**：链表、树、图都依赖指针连接节点。

```c
struct Node {
    int value;
    struct Node *next;      /* 自引用：结构体里放指向自己的指针 —— 合法 */
};
```

> 注意：`struct Node *next;` 合法，但 `struct Node next;`（放自己的实例）**不合法**——那会是无限递归的大小。这个"自引用指针"就是链表、树、图的全部秘密。

#### 7.7.3 内存布局与对齐（课件 49 页）

```c
struct A { char c;    int x; };   /* 1 字节 + 3 填充 + 4 = 8 */
struct B { char c1; char c2; int x; };  /* 2 + 2 填充 + 4 = 8 */
struct C { int x;  char c; };     /* 4 + 1 + 3 尾部填充 = 8 */
struct D { char c; double d; int i; };  /* 1 + 7 + 8 + 4 + 4 = 24 */
struct Node { int value; struct Node *next; };  /* 4 + 4 填充 + 8 = 16 */
```

**实测输出**（`02_struct_align.c`）：

```
sizeof(struct A) =  8,  offsetof(x) = 4
sizeof(struct B) =  8,  offsetof(x) = 4
sizeof(struct C) =  8,  offsetof(c) = 4
sizeof(struct D) = 24, offsetof(d) = 8, offsetof(i) = 16
sizeof(struct Node) = 16, offsetof(next) = 8
```

**三条对齐规则**：

1. 每个成员的偏移必须是**该成员对齐数**（通常是自身大小）的整数倍 → 中间产生填充；
2. 结构体总大小必须是**最大成员对齐数**的整数倍 → 末尾产生尾部填充（保证结构体数组里每个元素都对齐）；
3. 所以 `sizeof(struct)` **≥** 成员大小之和，且需用 `sizeof` 实测，不要手算。

**优化技巧**：把大成员排前面、同类型成员放一起，常常能省内存。`struct B` 与 `struct C` 都占 8 字节，但 `struct C {int; char;}` 只"浪费"3 字节填充，而 `struct A {char; int;}` 中间浪费 3 字节——布局顺序影响缓存友好性与可读性。

#### 7.7.4 结构体与动态内存结合（课件 50–51 页，**释放顺序是重点**）

```c
static struct Student *student_create(int id, const char *name, float score) {
    struct Student *s = (struct Student *)malloc(sizeof(struct Student));
    if (!s) return NULL;

    s->id = id;
    s->score = score;
    s->name = (char *)malloc(strlen(name) + 1);   /* +1 放 '\0' */
    if (!s->name) { free(s); return NULL; }        /* 分配失败：先把自己释放掉 */

    strcpy(s->name, name);
    return s;
}

static void student_destroy(struct Student *s) {
    if (!s) return;
    free(s->name);      /* 顺序 1：先释放内部成员 */
    s->name = NULL;
    free(s);            /* 顺序 2：再释放结构体本身 */
}
```

> **重要 1：释放顺序**（课件第 51 页原文）
> 动态分配的结构体若含有动态分配的内部成员（如 `char *name`），**必须先释放内部成员，再释放结构体本身**，否则会造成内存泄漏。

**为什么**：`free(s)` 只归还结构体那块内存，`s->name` 指向的字符串块与结构体块是**两次独立分配**。一旦 `s` 被释放，`s->name` 这个指针值就再也读不到了，那块内存永远无法回收。

**对称原则**：`malloc` 几次，就要 `free` 几次；谁分配，谁释放；**分配附近就写出对应的 `free()`**。

#### 7.7.5 结构体的赋值是"浅拷贝"（助教补充，L03 会踩坑）

```c
struct Student a = {202501, NULL, 95.5f};
a.name = strdup("张三");

struct Student b = a;      /* 逐字节复制：b.name 与 a.name 指向同一块内存！ */
free(a.name);
printf("%s\n", b.name);    /* 未定义行为：use-after-free */
```

**结论**：结构体赋值/传参/返回是**逐成员复制**。若成员里有指针，复制的是**指针值**，不是指针指向的内容。想真正复制，必须写"深拷贝"函数。

### 7.8 七种经典错误清单（课件第 47 页，逐条给你"症状 → 原因 → 修法"）

| # | 错误 | 症状 | 原因 | 修法 |
|---|---|---|---|---|
| 1 | 分配返回值未检查 | 随机崩溃、`NULL` 解引用 | 内存不足或 `size` 参数溢出 | 所有 `malloc/calloc/realloc` **必须判空**，失败立即返回或走统一清理路径 |
| 2 | 未初始化使用 | 输出随机数、结果不稳定 | `malloc` 返回脏数据 | `malloc` 后**立即显式初始化**，或改用 `calloc` |
| 3 | 悬空指针 | 时对时错、崩溃 | `free` 后继续读写；返回栈上地址 | `free(p); p = NULL;`；**绝不返回局部对象的地址** |
| 4 | 内存泄漏 | 长时间运行内存持续增长 | 丢失最后一个可达指针（被覆盖、异常路径、提前返回） | 分配附近就写出对应 `free()`；统一出口清理 |
| 5 | 二次释放 | `double free or corruption` | 两个路径都 `free` 同一指针 | 统一所有权：仅"唯一所有者"负责释放；释放后置 `NULL` |
| 6 | 越界访问 | 覆盖相邻变量、栈被破坏 | 下标/长度未做边界检查 | 封装容量与长度（如 `DynamicArray`），**所有写入前做边界检查** |
| 7 | `realloc` 误用 | 内存泄漏、丢失数据 | 直接 `arr = realloc(arr, n)`，失败时 `arr` 变 `NULL` | **总用临时指针接收返回值**，成功后再更新 |

**建议的验证手段**：

```sh
gcc -std=c11 -Wall -Wextra -g -fsanitize=address,undefined your.c -o your && ./your
```

`AddressSanitizer` 会直接报出越界、`use-after-free`、`double free`、泄漏，并给出出错的行号与调用栈。**练习阶段请默认打开这个选项。**

> 复习 C 语言指针、数组、结构体的概念，写一个简单的 C 程序，定义一个结构体表示学生信息（学号、姓名、成绩），并实现一个函数打印学生信息。

**参考解答**（完整可编译）：

```c
/* hw1_student.c */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#define NAME_MAX 64

struct Student {
    int    id;                 /* 学号 */
    char   name[NAME_MAX];     /* 姓名：定长数组，简单安全 */
    float  score;              /* 成绩 */
};

/* 按值传结构体：会复制整个结构体（此处仅 72 字节，可接受） */
static void print_student_by_value(struct Student s) {
    printf("[值传递] 学号: %d, 姓名: %s, 分数: %.2f\n", s.id, s.name, s.score);
}

/* 按指针传：只复制 8 字节，且 const 表明不修改 */
static void print_student_by_pointer(const struct Student *s) {
    if (!s) return;                                    /* 防御性检查 */
    printf("[指针传递] 学号: %d, 姓名: %s, 分数: %.2f\n",
           s->id, s->name, s->score);                  /* -> 等价于 (*s). */
}

int main(void) {
    struct Student stu;
    stu.id = 202501;
    snprintf(stu.name, NAME_MAX, "%s", "张三");         /* 比 strcpy 更安全：限长 */
    stu.score = 95.5f;

    print_student_by_value(stu);
    print_student_by_pointer(&stu);

    printf("sizeof(struct Student) = %zu 字节\n", sizeof(struct Student));
    return 0;
}
```

**要点讲解**

- `name` 用**定长数组**而非 `char *`：结构体自成一体，不需要额外的 `malloc/free`，适合作业；用 `char *` 则需要 `malloc` + 正确的释放顺序（见练习 3）。
- `snprintf(dst, size, "%s", src)` 比 `strcpy` 安全——它保证不会写超过 `size` 字节，并总是补 `'\0'`。
- 两个打印函数演示了**值传递 vs 指针传递**：值传递复制整个结构体；指针传递只复制地址。当结构体很大（比如含 1 MB 数组）时，这个差别是**秒级 vs 微秒级**。
- `const struct Student *s`：既避免复制，又向调用者承诺"我不会改你的数据"。

### 练习 5（助教加餐：找 bug）

下面这段代码有 **4 个**问题，请找出来并改正。

```c
#include <stdio.h>
#include <stdlib.h>

struct Node { int v; struct Node *next; };

struct Node *make(int v) {
    struct Node n;              /* (1) */
    n.v = v;
    n.next = NULL;
    return &n;                  /* (2) */
}

int main(void) {
    struct Node *head = make(1);
    printf("%d\n", head->v);
    return 0;                   /* (3) (4) */
}
```

**答案**

| # | 问题 | 原因 | 修法 |
|---|---|---|---|
| 1 | `struct Node n;` 定义在**栈**上 | 函数返回即销毁 | 改成 `struct Node *n = malloc(sizeof *n);` |
| 2 | `return &n;` 返回栈地址 | 悬空指针（编译器通常会警告 `-Wreturn-local-addr`） | 返回 `n`（堆指针）；并判空 |
| 3 | 没有 `free(head)` | 内存泄漏 | `free(head); head = NULL;` |
| 4 | 没有检查 `malloc` 返回值 | 可能解引用 `NULL` | `if (!n) return NULL;`，调用处 `if (!head) return 1;` |

**改正后**：

```c
struct Node *make(int v) {
    struct Node *n = (struct Node *)malloc(sizeof *n);
    if (!n) return NULL;        /* 检查分配失败 */
    n->v = v;
    n->next = NULL;
    return n;                   /* 返回堆对象的地址，函数返回后仍然有效 */
}

int main(void) {
    struct Node *head = make(1);
    if (!head) { fprintf(stderr, "分配失败\n"); return 1; }
    printf("%d\n", head->v);
    free(head);
    head = NULL;
    return 0;
}
```

> `malloc(sizeof *n)` 比 `malloc(sizeof(struct Node))` 更好：**改了类型不用改这行**，且不会写错类型。

## 9. 自测清单（先自答，再看答案）

1. **`p` 和 `*p` 有什么区别？`&p` 是什么意思？**
   > `p` 是指针变量，它的值是某个对象的地址；`*p` 是解引用，表示 `p` 指向的那个对象本身（可作左值）。`&p` 是**指针变量自己的地址**，类型是"指向指针的指针"（如 `int **`）。

2. **为什么说"指针的大小与所指类型无关"，但"指针的步长与所指类型有关"？**
   > 指针只需要存下一个地址，64 位平台固定 8 字节，与所指类型无关。但 `p + 1` 要移动到"下一个同类型对象"，所以前进 `sizeof(*p)` 字节——这是指针算术有类型的原因。

3. **`int *a, b;` 声明了什么？**
   > 只有 `a` 是指针，`b` 是 `int`。要声明两个指针必须写 `int *a, *b;`。

4. **`sizeof(arr)` 与 `sizeof(p)`（`p = arr`）为什么不同？**
   > `arr` 是数组类型 `int[5]`，`sizeof` 给出整个数组 20 字节；`arr` 在其它表达式里退化为 `int *`，`p` 就是 `int *`，大小 8 字节。这是"数组名退化"的例外之一。

5. **什么是"末端后一位"？为什么它合法但不能解引用？**
   > `arr + n`（n 为数组长度）指向最后一个元素的后面一位。C 标准允许**计算**这个地址用于循环终止判断，但它不指向任何对象，解引用是未定义行为。

6. **`malloc` 和 `calloc` 的区别？什么时候选 `calloc`？**
   > `calloc(n, size)` 会**清零**并检查乘法溢出；`malloc` 不清零。需要"默认值为 0"或想避免未初始化不确定性时用 `calloc`。

7. **`realloc` 失败时会发生什么？为什么不能写 `arr = realloc(arr, n)`？**
   > 失败返回 `NULL` 且**原内存保持不变**。直接赋值会把 `arr` 覆盖成 `NULL`，旧内存的地址永久丢失 → 内存泄漏。必须用临时指针接收，成功后再更新。

8. **为什么动态数组扩容要翻倍？给出均摊分析。**
   > 容量按几何级数增长时，前 n 次插入的总搬运量是 1+2+4+…< 2n = O(n)，均摊到每次是 O(1)。若每次只加 1，总搬运量是 n(n+1)/2 = O(n²)，均摊 O(n)。

9. **结构体为什么会有填充字节？`struct A {char c; int x;}` 占几字节？**
   > 为了让每个成员的地址满足其对齐要求（`int` 需要 4 字节对齐），编译器在 `c` 之后插入 3 字节填充；同时结构体总大小要是最大对齐数的倍数。共 8 字节（本机实测）。

10. **`struct Student *s` 里，`s->name` 与 `(*s).name` 的关系？释放时先 `free` 谁？**
    > 完全等价，`->` 是语法糖。释放时**先 `free(s->name)`，再 `free(s)`**；反了就会丢失 `name` 的地址造成泄漏。

11. **`clock()` 与 `clock_gettime(CLOCK_MONOTONIC)` 测的分别是什么？**
    > 前者测进程消耗的 **CPU 时间**（不含等待）；后者测**墙钟时间**（真实流逝时间，且单调不受时钟调整影响）。测纯计算量用前者，测用户感知响应时间用后者。

12. **你的函数耗时测量结果是 0.000000 秒，可能的原因有哪些？至少说三个。**
    > ① 编译器把被测代码优化删除（结果未被使用）；② 时钟分辨率不够（如 `clock()` 为 1 µs，而被测代码只有几十纳秒）；③ 被测代码确实极快，需要放进循环累计；④ 测量方式错误（如取了两点但中间没执行）。

13. **为什么链表节点必须放在堆上而不能放在栈上？**
    > 节点需要在"创建它的函数返回之后"继续存活。栈对象在函数返回时自动销毁，留在链表里的指针就成了悬空指针。

14. **`void *` 为什么不能直接解引用？**
    > 它的类型信息缺失，编译器不知道要读几个字节、按什么类型解释。必须先转换成具体类型指针（如 `(int *)v`）再解引用。
