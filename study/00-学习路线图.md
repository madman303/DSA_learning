## 2. 这门课到底在教什么：三条学习主线

初学者的错误是"把每讲当孤立知识点背"。这门课其实是**三条线并行推进**，每一讲都在三条线上各推进一步：

```
主线 A：C 语言与内存能力线（工具线）
   指针 → 动态内存 → 结构体 → 多文件工程/函数库 → 文件 IO → 调试与性能分析
   特征：越往后越像"软件工程"，而不是"写个 main 交作业"

主线 B：数据结构线（对象线）
   数组 → 动态数组 → 单链表 → 双链表/循环链表/静态链表 → 栈/队列 → 树 → 散列表 → 图
   特征：每种结构都在回答同一个问题——"数组不够用了，换什么？"

主线 C：算法分析线（思维线）
   计时与复杂度 → 递归与递推式 → 分治 → 排序 → 链表算法 → 图算法 → 动态规划/贪心/智能算法
   特征：核心技能是"看着代码说出它的时间复杂度"，以及"看着问题选对复杂度级别"
```

**三条线的交汇点**就是本课程的成绩：**给你一个现实问题（如校园路径规划、推荐系统相似度、ASEP 模型、Gantt 图），你能抽象出数据结构、选对算法、用 C 写出来、并用数据证明它够快。**

## 4. 知识依赖图：为什么必须按这个顺序学

```
                    ┌────────────────────────────────────────────┐
                    │ L01  指针 / 动态内存 / 结构体 / 计时         │  ← 地基，不可跳
                    └───────────────────┬────────────────────────┘
                                        │  （没有指针，后面寸步难行）
                    ┌───────────────────▼────────────────────────┐
                    │ L02  递归 / 递推式 / 分治 / 三种排序         │
                    │      产出：能分析复杂度、会写库、会指针数组   │
                    └───────────────────┬────────────────────────┘
                                        │
              ┌─────────────────────────▼──────────────────────────┐
              │ L03  数组的局限 → 单链表（结构、C 实现、哨兵、       │  ← 全课核心
              │      删除三写法、内存释放、ASEP 应用、分治附录）      │
              └─────────────────────────┬──────────────────────────┘
                                        │
              ┌─────────────────────────▼──────────────────────────┐
              │ L04  链表复杂操作 → 链表排序 → 双链表/循环/静态链表  │
              │      → C 工程组织（.h/.c、.so、Makefile、文件 IO）    │
              └─────────────────────────┬──────────────────────────┘
                                        │
                     ┌──────────────────▼───────────────────┐
                     │ 后续：栈与队列 → 树/AVL → 散列 → 图/最短路 │
                     └──────────────────────────────────────┘

   并行的实验线：
     Lab01（Git + 指针实验 + 计时）—— 与 L01/L02 同步做，教会你"交作业"和"量性能"
     Lab02（格子数组/链状节点 + 栈队列 + 随机行走 + BFS 寻路）—— 在 L03/L04 之后做，
            它是"数据结构如何支撑一个完整模拟程序"的综合演练
```

**三条硬依赖（跳了必卡）**

1. **指针 → 链表**：链表就是"用指针把一堆堆上的节点串起来"。不懂 `p->next = q` 就去学链表，只会抄代码。
2. **递归与分治 → 链表排序与树**：L04 的链表归并排序、后续的树遍历，全是递归。
3. **动态内存 → 一切动态结构**：忘记 `free`、搞错释放顺序，程序"能跑但错"，这是最危险的失败模式。

## 9. 十个高频卡点与破解方法

| # | 卡点 | 症状 | 破解方法 |
|---|---|---|---|
| 1 | 指针看不懂 | 能读懂代码，自己写就错 | 每写一行指针操作，**先画内存图**再写代码。用 `printf("%p", (void*)p)` 打印真实地址 |
| 2 | `*` 与 `&` 混淆 | `*p = &x` 之类的错 | 记住：`&` 是"到哪里"，`*` 是"到那里去"。多级指针从右往左读 |
| 3 | 改指针顺序导致断链 | 链表后半截丢失 | 头插三步固定顺序：**先接新节点的 next，再改前驱的 next**。永远不要先丢引用 |
| 4 | `malloc` 后不检查、不初始化 | 随机崩溃 | 每个 `malloc` 后面紧跟 `if (!p) {...}`；初始化用 `calloc` 或立即赋值 |
| 5 | 忘记 `free` / 释放顺序错 | 内存持续增长；`double free` | `create`/`destroy` 成对写；**默认打开 `-fsanitize=address`** |
| 6 | 引用 vs 值分不清 | C 里函数改了参数，调用者没变 | C 想改调用者的东西，**必须传指针**（改指针本身则要传 `int **`） |
| 7 | 递归写不出 / 栈溢出 | 递归函数思路不清 | 递归两要素：**基准情形 + 向基准收敛的递推**。先写基准，再写递推 |
| 8 | 复杂度分析靠感觉 | 说不出为什么快排平均 O(n log n) | 每写一个算法就画**递归树**，写出递推式再解 |
| 9 | 计时结果不可信 | 测出来是 0，或每次都不一样 | 重复取最小值；用循环放大到可测；确保结果被使用；报告编译选项 |
| 10 | Git 提交出事故 | 冲突、推不上去、评 D | 提交前必做：`git status` → `git pull --rebase` → 解决冲突 → `git push`。详见 Lab01 讲义 |
