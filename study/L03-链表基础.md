## 1. 从数组到链表

### 1.1 数组的三条局限

| 局限 | 具体表现 | 后果 |
|---|---|---|
| **① 容量固定** | `int a[100]` 只能装 100 个（VLA 也不能改大小） | 要么浪费内存，要么不够用 |
| **② 插入/删除昂贵** | 在中间插入一个元素，后面所有元素都要后移 | 插入是 O(n)，且要搬运大量数据 |
| **③ 内存必须连续** | 需要一整块连续空间 | 内存碎片多时**分配不出来**；大数组尤其明显 |

> 注意：数组也有**链表给不了**的优点——**按下标随机访问是 O(1)**，而且**缓存友好**（数据连在一起，CPU 预取有效）。链表访问第 i 个元素要从头走 i 步，是 O(n)。
> **所以"用哪个"不是"哪个更好"，而是"哪个操作是热路径"。**

### 1.2 结构与定义

```
        head                        tail
         │                           │
         ▼                           ▼
    ┌─────────┬──────┐   ┌─────────┬──────┐   ┌─────────┬──────┐
    │ val = 5 │ next │──▶│ val = 3 │ next │──▶│ val = 1 │ next │──▶ NULL
    └─────────┴──────┘   └─────────┴──────┘   └─────────┴──────┘
      节点1                节点2                节点3（尾节点）
```

**四个术语，必须分清**

- **节点（node）**：一块堆内存，含"数据域"和"指针域"。C 里就是 `struct`。
- **头节点（head）**：链表**第一个节点**的指针。**链表本身用这个指针代表**。空链表 = `head == NULL`。
- **尾节点（tail）**：`next == NULL` 的那个节点。
- **NULL**：表示"没有后继"。**它不是节点，不占内存，不能解引用。**

**为什么 `next` 必须是指针，不能是节点本身？**

```c
struct Node { int val; struct Node *next; };   /* ✅ 合法：指针大小固定（8 字节） */
/* struct Node { int val; struct Node next; }; ❌ 不合法：大小无限递归 */
```

### 1.3 内存代价对照（作业题三要考）

| 对比项 | 一维数组 | 单链表 |
|---|---|---|
| **存储结构** | 一整块连续内存，n 个元素紧密排列 | n 个独立节点，用指针逻辑相连，物理上不连续 |
| **内存分配** | 一次性分配（编译期或 `malloc` 一次） | 每个节点单独 `malloc`，n 次分配 |
| **访问第 i 个元素** | 1 步：`base + i * sizeof(T)` | i 步：从 head 沿 `next` 走 i 次 |
| **插入/删除（已知位置）** | 平均 n/2 次元素搬移 | 改 1～2 条指针 |
| **额外开销** | 0（无元数据） | 每个节点多一个指针（64 位平台上 8 字节，占节点一半） |
| **缓存友好性** | 好（连续，预取有效） | 差（跳跃访问，易缺页/失效） |
| **容量** | 固定 | 按需增长，只受可用内存限制 |

> 作业题三的要求是"**写出步骤本身，不停在复杂度结论上**"。比如不要说"数组插入是 O(n)"，要说"在第 i 个位置插入，需要把第 i 到第 n-1 个元素各搬一次，共 n−i 次赋值，再加一次写入"。

### 1.4 选型判据

- 频繁**按下标随机访问**，且大小可预估 → **数组**
- 频繁在**中间插入/删除**，或**大小事先不知道** → **链表**
- 都要？→ 合理组合（例如：用数组存数据、用链表维护顺序；或第 4 讲的**静态链表**用下标模拟指针）

## 2. 单链表的基本操作

### 2.1 遍历：一切操作都要从 head 走一遍

链表**没有下标**，只能从头开始沿 `next` 走。所以：

```c
/* 骨架：遍历打印 */
void list_print(const Node *head) {
    /* TODO：循环条件是什么？空链表应该打印什么？ */
}

/* 骨架：求长度 */
size_t list_len(const Node *head) {
    /* TODO：为什么这个函数"必须"遍历，不能 O(1)？ */
}
```

**要点**：循环里**先保存 `next` 再用**，或者用 `for (p = head; p; p = p->next)` 的写法。**不要**在循环体里 `free(p)` 之后还去读 `p->next`（这是最常见的 use-after-free）。

### 2.2 插入：头插与尾插的代价差在哪里

**头插 O(1)**：

```
插入前:  head ──▶ [A] ──▶ [B] ──▶ NULL
第①步:   新节点 n：n->next = head        （n ──▶ [A] ──▶ [B] ──▶ NULL）
第②步:   head = n                        （head ──▶ [n] ──▶ [A] ──▶ [B] ──▶ NULL）
```

**尾插 O(n)**：必须**从头走到尾**找到最后一个节点，才能把它接到末尾；如果链表只给 `head` 一个指针，这个"找尾"的过程就是 O(n)。（想 O(1) 尾插？维护一个 `tail` 指针——但要记得在所有修改末尾的操作里同步它。）

**为什么头插两步的顺序不能颠倒？**

```c
/* ✅ 正确 */
n->next = head;
head = n;

/* ❌ 错误：head 已经被覆盖，原来的整条链找不到入口 → 永久内存泄漏 */
head = n;
n->next = head;      /* 此时 head == n，写成 n->next = n，自环！ */
```

**口诀：先接后继，再改前驱。**

### 2.3 删除：为什么必须先拿到前驱

要摘掉节点 X，必须让**X 的前驱**跳过 X：

```
删除前:  [P] ──▶ [X] ──▶ [S]
删除后:  [P] ───────────▶ [S]        （然后 free(X)）
```

而 `next` 是**单向**的：站在 X 上**无法回到 P**。所以：

- **必须从 head 出发，边遍历边保存前驱**；或者
- 用**指向指针的指针**（二级指针）避免显式的前驱变量（见 3.3）。

**特殊情形必须单独想清楚**：删的是**头节点**（没有前驱，要改 `head` 本身）。漏了它就必错。

### 2.4 反例：改指针的顺序不能颠倒

删除时同样有顺序陷阱：

```c
/* ❌ 错误：先 free 再读 next → use-after-free */
free(p->next);
p->next = p->next->next;     /* 已经释放的内存，读到的是垃圾 */

/* ✅ 正确：先存后继，再改指针，最后才 free */
Node *dead = p->next;
p->next = dead->next;        /* 先接后继 */
free(dead);                  /* 再释放 */
```

**口诀：先存后继，再 free。**

## 4. 综合应用：ASEP 的链表实现（作业题二/本周核心）

### 4.1 模型定义（课件 79 页）

**ASEP = Asymmetric Simple Exclusion Process（不对称简单排斥过程）**：一条**一维格点链**加若干**粒子**，粒子按**不同的概率**向两个方向尝试跃迁，**只有目标格点为空时移动才成功**。

**四个术语（第一次出现，必须背准）**

| 术语 | 定义 |
|---|---|
| **格点（site）** | 格点链上的一个位置，**最多容纳一个粒子**。链长记作 $L$，格点按顺序相接 |
| **粒子（particle）** | 占据在某个格点上的对象，用一个**编号**标识它。粒子数记作 $N$ |
| **排斥原则（exclusion）** | 每个格点最多只能有一个粒子，两个粒子不可能同时在同一格点 |
| **周期性边界（periodic boundary）** | 链的两端相接，粒子从一端走出就从另一端出现。因此**每个格点都有两个邻居，没有端点特例** |

**模型的三条核心特征**：**排斥**（唯一相互作用是"阻断"）、**随机**（是否移动由概率决定）、**不对称**（$P_{前进} \ne P_{后退}$）。

### 4.2 更新口径（**作业必须写明用哪一条**）

> 实现要求说"每一步对所有粒子各尝试一次跳跃"，这句话**必须补一条口径**才没有歧义：
> **目标格点在步首为空才算成功；同一个大步里两个粒子同时选中同一个空格点时，两个都不动。**

两条都合法，但**整份实现只能用一个口径**，且必须在 README 里写明：

- **平行更新**：所有判定基于**步首**的状态；
- **顺序更新**：判定基于**当时最新**的状态。

课件参考实现用的是**平行更新 + 同格点冲突则都不动**。理由是"可比较性"：口径不写清，两次运行的统计量没有对照的意义。

### 4.3 实现要求六条（作业题二正文要求，原文照录）

1. 支持**周期性边界条件**，粒子到达一端时从另一端出现。
2. 系统长度 $L \ge 50$，粒子密度 $\rho = N/L$ 满足 $0.5 \le \rho \le 0.9$。
3. 跳跃概率满足 $P_{前进} \ne P_{后退}$，且两者取值都在 $[0.2, 0.8]$ 之内。
4. 每次模拟运行的步数**不少于 5000 步**，每一步定义为对所有粒子各尝试一次跳跃。
5. 把所有粒子的轨迹 $x(t)$ 画在一张图里，横轴是步数，纵轴是格点编号。
6. **语言限定 C 或 Julia；格点与粒子都用链表表示，不使用数组**；把链表结构与算法**封装成模块**便于复用与测试；代码要有注释。

### 4.4 验证方式五条（作业的验收依据，原文要点 + 实测数字）

说明文档里必须**逐条给出期望值、实测值与结论**。

| # | 验证 | 内容与课件的实测 |
|---|---|---|
| 1 | **小规模手算对照** | 取 $L=2, N=1, P_{前}+P_{后}=1$：链上只有一个粒子，另一个格点必定为空，所以粒子**每一步都必定移动**；两个方向的目标是同一个格点，结论**与随机数无关**。粒子在第 1、3、5 步落在 2 号格点，第 2、4、6 步回 1 号。实测 10 步完全符合，位串按 `x.` 与 `.x` 交替 |
| 2 | **守恒检查** | 格点数与粒子数全程不变；每个格点的占据数**始终不超过 1**。实测 $L=50, N=40$、5000 步：粒子数始终 40，占据数上限始终 1 |
| 3 | **漂移方向检查** | 单粒子时没有阻断，净位移 = 向前次数 − 向后次数，期望 $(P_{前}-P_{后})\times$步数；一步位移的方差 $= P_{前}+P_{后}-(P_{前}-P_{后})^2$。实测 $L=50$、$P_{前}=0.7, P_{后}=0.3$、5000 步：向前 3494、向后 1506、净位移 **1988**，期望 **2000**，5000 步标准差 **64.8**，偏差 −12（即 **−0.185 个标准差**）。方向为正，与不对称偏向一致 |
| 4 | **固定种子复现** | 同一随机种子下两次运行的摘要**逐字相同**。实测两次都是 2000 步累计跳跃 11241 次，末态位串逐字相同。注意"可复现"指**同一份代码、同一个种子、同一台机器**上的同一串结果 |
| 5 | **账目闭合**（最有用） | 每次尝试只有三种归属：**目标被占失败 / 抢同一空格点失败 / 成功跳跃**，三者之和必须等于尝试总数。实测 5000 步：尝试 $5000\times40=200000$，其中被占失败 154612、抢同格失败 17290（8645 处冲突，每处两个粒子）、成功跳跃 28098 —— 三数之和正好 200000 |

> 为什么第 5 条最有用：它能抓住一整类错误——粒子数忽然少了（有人把占据标记盖掉了）、成功数多于尝试数（有人让一条粒子多动了一次）、**冲突数长期为零**（双向模型里不可能为零，说明"后退"这一路根本没接上）。

### 4.5 参考实现的骨架思路（**抄了等于没做**）

课件给的骨架思路（在 `examples/` 下，本文不抄代码）：

- 格点链是**一条首尾相接的节点链**；
- 节点保存：**占据标记**（0 表示空格点，否则是粒子编号）、**本步方向**、**冲突登记字段**；
- 一个"大步"分**三遍走链**：① 清登记；② 抽方向并登记申请；③ 按申请数裁决移动。每遍 $L$ 个格点；
- **关键顺序**：抽到方向之后**必须先看目标格点是否为空**，不能先登记再筛。

## 6. 常见错误（错在哪 → 怎么改 → 为什么）

| 错误 | 症状 | 原因与改法 |
|---|---|---|
| 头插顺序颠倒 | 链表只剩一个节点（自环） | 先接后继再改前驱 |
| 删除前先 `free` | 读到垃圾 / ASan 报 use-after-free | 先存后继，再改指针，最后 free |
| 忘了删头节点的特判 | 头节点删不掉 | 用二级指针或哨兵 |
| `free` 了节点但没改 `head` | 悬空指针 | 参数用 `Node **` 或返回新 head，并让调用者接住 |
| 只 `free(head)` | 整条链除头之外全部泄漏 | 必须逐个遍历释放 |
| 用数组存格点 | 违反 ASEP 要求 6 | 格点与粒子都用链表 |
| ASEP 没写更新口径 | 统计量无法对照，验收不过 | README 写明平行/顺序更新 + 冲突规则 |
| 冲突数长期为 0 | 说明"后退"根本没接上 | 用第 5 条账目闭合检查 |
| 随机不可复现 | 无法做验证 4 | 显式设种子并写进 README |
