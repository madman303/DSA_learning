附录三件事：分治、递归与循环
链表主线走完之后，本讲加一个附录，把正文里反复使用但没有抽出来的三种思维收成一般形式。附录讨论三件事：第一，
分治的一般结构：把原问题划成若干规模更小的同类子问题（分），再从最小子问题出发把解合并回去（治），交代这套结
构成立的前提、分解终止的基线，以及两个可调参数（每次分几份、分到什么规模停）。第二，同一个算法在分治中的两种
写法：递归写法把分与治写成一个函数的自我调用，层次的推进交给调用栈隐式保存；循环写法把分的层次显式化为外层
循环、把治写成内层合并。第三，选型问题：哪些场合适合递归、哪些场合适合循环，给出判据与反例。
附录末尾回答一个被反复混淆的问题：分治不等于 𝑂(log𝑛)。二分查找能做到 𝑂(log𝑛)，靠的不是把区间分成两半，而是分
完之后能根据比较结果把一半弃掉；把集合分成若干份再求和，每一份仍然要访问，复杂度不会低于 𝑂(𝑛)。递归与循环的
差别，在数组上两者都写得出来、看不分明，换到链表上（删除与释放最容易撞到递归深度这一层）才暴露出来，所以这
三件事放在链表讲完之后收。

为什么需要链表：数组的三条局限
数组（array）是一段连续的内存，存放同一类型的元素，元素的位置由首地址加上下标乘元素大小的偏移量算出。这条“地
址能算出来”的性质是数组全部优点的来源：按下标访问任何元素都是 𝑂(1)，没有额外的结构开销，连续排布还让相邻元素
一起被带进高速缓存（CPU 与内存之间的一层小块快速存储，一次访存会把相邻数据一并搬进来）。
三条局限也从这条性质来，它们都是“连续”二字的直接后果。
1.要求一整块连续空闲内存：元素越多，要申请的连续区间越长。程序运行一段时间之后，内存被反复申请与释放切成碎片，
空闲总量可能远大于数组所需，却找不出一块足够长的连续区间，于是大数组分配不出来。
2.容量在分配时定死：数组的长度一经分配就固定，要放更多元素，只能另外申请一块更大的连续区间，再把原有元素逐个复
制过去，复制量正比于原长度，代价 𝑂(𝑛)。
3.头部与中间插入、删除要搬移元素：在数组的第 1 个位置插入一个元素，后面的每个元素都要向后挪一格；元素越多，挪得
越多，代价 𝑂(𝑛)。删除同理，被删元素之后的元素要整体前移。
链表正是为回避这三件事而存在的：节点各自单独申请，因此对连续区间没有要求；插入一个元素才申请一个节点，因此
不存在“扩容”；插入与删除只改动少数几个指针，因此不必搬移元素。
淘汰数组当然不是结论。数组三条优点的价值没有变，链表换来的只是那三类操作上的便宜；这笔便宜要连着代价一起算，
见选型一节。

链表的结构与定义：节点、头节点、尾节点与空值
链表（linked list）是一种线性数据结构：每个元素各自存放在一个节点里，节点之间用指针连接，元素的先后次序由这些
指针给出。
四个术语在这里给出完整定义。
节点（node）：链表的基本单元，由数据域与指针域两部分组成。数据域存放元素本身；指针域存放下一个节点的地址，在 C
里是指针，在 Julia 里是对象引用。
头节点（head node）：链表中排在最前面的节点，它的地址保存在 head 变量中。head 是链表的入口，拿到 head 就能顺着指
针走到链表的任何位置。
尾节点（tail node）：链表中排在最后面的节点，它的指针域为空，表示后面没有节点了。
空链表：没有任何有效节点的链表，此时 head 为空。
空值在两种语言里的记法不同：C 里是 NULL，Julia 里是 nothing。空值表达的是“后面没有节点”，它不是数据，读它的数据
域是错误。
链表与数组的分水岭是一句话：节点在内存中的位置不必相邻，元素的次序完全由指针给出。数组的地址能由下标算出来，
所以能随机访问；链表的节点位置与元素次序无关，只有指针知道下一个节点在哪里，取第 𝑘 个元素必须从 head 出发走
𝑘−1 步，只能顺序访问。这条差别是后面所有代价差异的源头。

存储表示、内存代价与指针／引用的差异
存储表示：节点分散在内存各处，head 保存第一个节点的地址，尾节点的指针域为空。数组与链表的区别可以这样记：数
组的次序写在地址里，链表的次序写在指针里；地址是算出来的，指针是一格一格跟着走的。
内存代价：每个节点除数据域之外还要多存一个指针域，所以存同样多的元素，链表比数组多占内存。实跑数字（脚本：
examples/array_vs_list_cost.c 与 examples/array_vs_list_cost.jl）：C 侧 sizeof(int) 是 4 字节、sizeof(Node) 是 16 字节
（数据 4 加指针 8，多出的 4 字节是编译器为对齐插入的填充）；Julia 侧 sizeof(Int) 是 8 字节、sizeof(Node) 是 16 字节。存
500 万个整数，C 侧数组实测 20 MB、链表实测 80 MB，链表是数组的 4 倍。
同一个 next 在两种语言里的两种含义：
C 侧的 next 是指针，存放的就是一个内存地址。取地址与解引用都要程序自己写出来，节点的内存用 malloc 申请、用 free
归还，空值是 NULL；谁申请谁归还，编译器不替程序记账。
Julia 侧的 next 是对象引用，地址不可见。节点由构造函数生成，回收交给垃圾回收（运行时自动找出不再被引用的对象并归
还其内存），空值是 nothing；节点字段写成 Union{Node,Nothing}，把“要么指向一个节点、要么为空”写进类型，读之前必须
先判空。
两侧的分工可以用一句话概括：C 交出对内存的完全控制，同时交出全部责任；Julia 用类型与回收器换掉内存泄漏与悬空
指针两类错误，代价是释放时机不由程序指定。逐项对照见下方详解块。

选型判据：什么时候用数组，什么时候用链表
判据从本课程自己的三个场景里抽出来，不从清单上背。
场景一，随机行走的格子状态表（实验二的数组版）：程序维护一张格子状态表与一张统计结果表，每走一步都要读当前格子
的计数再加一，收尾时还要按下标读任意格子的结果做统计。这里的访问以随机访问与顺序扫描为主，格子数在开始前就定
下来、不再变化。索引直接算出地址，数组是自然的选择。
场景二，同一个随机行走改用链表表示（实验二检查点②）：把每个格子位置存成一个链表节点，功能与场景一完全相同。这
是刻意安排的“同一功能换表示”：换成链表之后插入与删除变成改指针，但按下标取某个格子必须顺着链走，两种实现在访
问、插入与内存占用上的差异要亲手量出来写进报告。
场景三，大自然数运算（实验三）：一个大数的每一位存成一个节点，低位在前。做加法时从低位起逐位相加，每算出一位就
接到结果链表的头部，进位还可能让结果比原来更长。这里的写操作集中在头部插入，位数事先不知道，每一位又都是刚算
出来的新元素，链表正好对口。

三条边界提醒，第一条是本讲最要紧的一句。
1.链表不是更快，而是在另一类操作上更便宜。 链表把数组里“搬移元素”的代价换成了“找位置”的代价。有下标要取元素时，
链表一定比数组慢；只有已经站在前驱节点上做插入删除，链表才快。上一节实跑全表的第二、三行正是这两个方向：头部
插入链表赢、顺序求和数组赢，谁也不能抵消谁。
2.数组的连续存储带来缓存优势，常数因子往往比复杂度表更好看。 复杂度只数操作次数，不问这一次访存是否命中缓存。连
续排布让一次访存顺带把相邻元素带进高速缓存，于是两个同样标着 𝑂(𝑛) 的写法实测可以差一个数量级。判断性能时，复
杂度决定趋势，常数决定当下。

遍历：一切链表操作都要从 head 走一遍
定义：遍历（traverse）指从 head 出发取当前节点的数据，再沿当前节点的 next 前进到下一个节点，重复到空值为止。空
值在 C 里是 NULL，在 Julia 里是 nothing。
动机：为什么遍历是链表一切操作的基础？因为链表除了 head 之外没有第二个入口。节点分散在内存各处，谁也不是靠下
标就能算出来的。要在链表上做任何“定位”的事，找第 𝑖 个节点、找值为 𝑥 的节点、找尾节点、找某个节点的前驱，唯一的
办法就是从 head 顺序走一遍。插入、删除、反转、合并、判环都以“先找到某个位置”为前提，遍历是这些操作共同的底
座。
代价：按序号访问与按值查找都要从 head 顺序走，最坏情况走完整条链，代价 𝑂(𝑛)。这与数组的 𝑂(1) 随机访问正好相
反：数组用首地址加下标一步算出地址，链表只能用“前进 𝑖 次”换到第 𝑖 个节点（本节下标都从 0 起）。顺序访问
（sequential access）说的就是这件事：节点之间的次序完全由指针给出，只能一个接一个地取。

插入：头插与尾插的代价差在哪里
定义：插入指在链表中增加一个新节点，做法是改指针而不搬元素。这与数组插入形成对照：数组在头部或中间插入要把
后面的元素整体后移，代价 𝑂(𝑛)；链表只需要改动两条指针的指向。
头插（push front）：新节点的 next 指向原来的 head，再把 head 指向新节点。如果已经持有 head，这是两步操作，代价
𝑂(1)，一个节点都不用访问。尾插（push back）：新节点要接在尾节点后面，问题是要先把尾节点找到，而单链表只有从
head 出发的路径，所以得沿 next 走完整条链，代价 𝑂(𝑛)。
中间插入：先找到前驱 prev，然后新节点的 next 接后继，prev 的 next 接新节点。找前驱本身要从 head 走，代价 𝑂(𝑛)；拿
到前驱之后的改指针是 𝑂(1)。
头插与尾插都只是改指针，两者的差别全在“改之前要不要先走一遍找位置”。这一点上是链表与自己比，而链表与数组比
时，这条差异会反过来：数组的头插要把所有元素后移（𝑂(𝑛)），链表的头插是 𝑂(1)；数组往末尾追加可以在末尾写（均
摊 𝑂(1)），链表不额外维护尾指针时反而要先走一遍（𝑂(𝑛)）。头插便宜、尾插贵是本节第一个反直觉的地方。

删除：为什么必须先拿到前驱
定义：删除指把一个节点从链表中摘掉（在 C 里还要释放它占用的内存）。与插入一样，删除只改指针，不搬元素。
动机：单链表每个节点保存的是指向后继的指针，被删节点自己并不知道它的前驱是谁。要把前驱的 next 跨过被删节点，
就必须先拿到前驱；而拿前驱的唯一办法是从 head 顺序走一遍。这是单链表的一条固有代价，也正是双链表存在的理由之
一：双链表每个节点多存一个指向前驱的指针，删除时不必再找前驱，代价是每个节点多一个指针的内存，以及插入与删
除时要成对维护两条指针。
步骤（按值删除第一个等于 key 的节点）：先找到前驱 prev；把 prev 的 next 改成 victim 的 next，跨过被删节点；再释放
victim。三步的次序不能乱，下一小节专门讲这一点。
边界：如果被删的正好是头节点，它没有前驱，要改的是调用者的 head 本身。C 里这时形参要写成二重指针 Node **head，
或者在链表头部预先放一个哨兵节点让删头与删中间在程序结构上等价。这两条路子在后面的 C 实现一节展开，本节先把
这段边界点出来。

反例：改指针的顺序不能颠倒
链表代码真正麻烦的地方不在“不知道该改哪个指针”，而在“知道该改哪两条却改反了顺序”。两条指针里，凡是要用到的那
个值只有一份拷贝，先覆盖它该去的地方就丢了。
反例一：中间插入的顺序颠倒。 正确顺序是先让新节点的 next 接上后继，再让前驱的 next 转向新节点。反过来的写法是：
void insertAfterBad(Node *prev, int data) {
Node *p = createNode(data);
prev->next = p; // 前驱先指向新节点
p->next = prev->next; // 再取前驱的 next，取到的却是新节点自己
}
第二步里的 prev->next 已经在第一步被改写成了新节点自己，于是新节点的 next 指向自己，形成一个自环；原来后半条链
（节点 3 与 4）在内存里还在，但再也没有任何指针能从 head 走到它们。实测输出：
顺序正确 插入前: 1 -> 2 -> 3 -> 4 -> NULL
顺序正确 插入后: 1 -> 2 -> 25 -> 3 -> 4 -> NULL
顺序颠倒 插入前: 1 -> 2 -> 3 -> 4 -> NULL
顺序颠倒 插入后: 1 -> 2 -> 25 -> 25 -> 25 -> 25 -> 25 -> 25 -> 25 -> 25 -> ...（打印到第 10 个节点仍未走到 NULL）
新节点的 next 指向自己吗: 是（成了自环）
节点 3 还在链表里吗: 在，但已无法从 head 走到
注意这段输出里最要紧的一句是最后一行：节点 3 并没有消失，它还在内存里，只是从 head 出发再也走不到。这类错误在
链表上叫断链，它既不会让程序立刻报错，也不会让编译器发出警告。

反例二：删除时把释放与取后继的顺序颠倒。 下面这段先 free 再取 victim->next：

别处重用，同一份代码可能今天看起来对、明天崩。
一般规则：改指针之前先把所有还要用到的值保住，再覆盖。
插入时要保住的是后继的地址，它只存在 prev->next 这一份拷贝里，所以新节点的 next 必须先接上它。
删除时要保住的是 victim->next，被删节点一旦释放就取不到了，所以必须先把值取出来（或者先把前驱的 next 改完再释
放）。
本节给这件事的口诀是先接后断：先把新节点的 next 接到该接的地方，再去断开或改写旧的那条指针。

三种写法的取舍：边界条件是麻烦的根源
三份代码摆在一起，能看出一个比“哪种写法更快”更要紧的结论。
麻烦的根源是删头节点这一条边界。 链表的第一个节点没有前驱，任何“改前驱的 next”的操作对它都失效。链表代码里七
成以上的绕，绕的都是这一处：双指针法里那个 prev == NULL 分支、哨兵法里那个多余的 dummy、递归法里那个“返回值就
是新头”的约定，全是为它准备的三种形状。
三者的取舍：
双指针法：不动链表结构、不多占一个节点、不需要调用者接收返回值，接口最“朴素”；代价是形参变成二重指针，且函数
体里始终有一条只在边界执行的支路。适合写进函数库时对外接口要稳定的场合。
哨兵法：删头与删中间用同一段代码，边界被“消灭”而不是“处理”；形参是一重指针，函数体只有一条主路径。代价是恒多一
个节点（本课示例把哑节点放在栈上，所以不占堆、不需要释放），且调用者必须把返回值赋回 head，漏掉这一句就等于什
么都没删。
递归法：代码最短，边界条件的处理被“交回上一层”这个动作顺带完成了；代价是栈深 O(n)，链表一长就会爆栈，而且每一
步都要做一次函数调用，常数因子比另两者大。
选择的标准：
链表长度可达数百万级、或者要写成函数库的正式接口，取哨兵法或双指针法。
链表长度有限（几千以内）、或者正在用递归思路推导算法（比如链表上的归并排序），取递归法。
三者都不是错的做法，写代码时能说清自己选了哪一种、为什么不选另一种，比记住“哪一种最好”有用得多。

哨兵思想与链表结构体：从特判到等价
把两种删除写法的具体差别抽成一般形式，可以得到一个在数据结构的代码里反复出现的思维手法：等价化，用一个无害
的额外对象，把一种特殊情形化成一般情形，从而消除代码里的特判。一条只在边界执行、却与主路径语义相同的支路，
是错误的高发地，因为它平时不被测试覆盖，出问题也只在极端输入上暴露。
它的适用条件与代价：
收益：特判被消灭，主代码只剩一条路径，测试覆盖与阅读负担同时下降。
代价：结构里恒多一个多余对象。对本课的链表就是“链表恒多一个节点，有意义的数据总从第二个节点开始”，任何按位置
计数的代码（第 i 个节点、长度、打印）都要记得这件事。
关键判断：代价是一次性的（初始化时付一次）、局部的（只在涉及头部时注意），而收益是在每一次函数体里持续兑现的。
所以这类替换几乎总是划算的。
推演链条是三步：看清痛点（双指针法的 if (prev == NULL) 支路与主路径语义相同却写法不同）；问一句“能不能让它不存
在”（如果头节点也有一个前驱，删头就变成删中间）；得到一般形式（在头部前置一个不存有意义数据的节点，它就是“原
head 的前驱”）。
哨兵法用的是这个手法的临时版本：哑节点在栈上，只在一次函数调用内存在，函数返回就“撤销”了等价化。如果一条链
表的每个操作都怕删头，那就把这个哑节点固化下来：initLinkedList 直接返回一个哑节点，此后所有操作都默认“头节点
是哑节点”。

NULL、悬空指针与解引用的安全边界
指针的安全边界是本讲最容易出错、也最容易忽略的地方。
三个术语先定义清楚：
空指针：取值 NULL 的指针，它不指向任何有效对象。判空是链表中每条遍历、每次取成员之前的常规动作。
悬空指针（dangling pointer）：曾经指向一块有效内存、而那块内存已经被释放的指针。它的值不一定等于 NULL。
野指针（wild pointer）：从未被初始化、值不确定的指针变量。它的值同样不一定等于 NULL。
解引用的安全边界：*p、p->data、p->next 都要求 p 指向一块仍然有效且属于本程序的内存。这条边界与“是不是 NULL”是
两件事：
NULL 判空只能拦住空指针。
悬空指针与野指针的值通常不是 NULL，判空对它们毫无反应，代码会一路走到“读一块已经被释放或从未属于程序的内存”上
去。
所以“每次用之前判一下空”是不够的，真正的边界是所有权：谁 malloc、谁 free，并且 free 之后必须让所有还持有这个地
址的变量失效（置空），让“这块内存还能不能碰”这件事变成可以从变量取值判断出来的事实。

ASEP 是什么：模型定义与练习要求
定义：ASEP（Asymmetric Simple Exclusion Process，不对称简单排斥过程）是一条一维格点链加若干粒子，粒子按不同的
概率向两个方向尝试跃迁，只有目标格点为空时移动才成功。四个术语在这里第一次出现，先给完整定义。
格点（site）：格点链上的一个位置，最多容纳一个粒子。格点链的长度记作 𝐿，格点按顺序相接。
粒子（particle）：占据在某个格点上的对象，本节用一个编号标识它。粒子数记作 𝑁。
排斥原则（exclusion）：每个格点最多只能有一个粒子，两个粒子不可能同时待在同一个格点上。
周期性边界（periodic boundary）：链的两端相接，粒子从一端走出就从另一端出现，因此链上每个格点都有两个邻居格点，
没有端点特例。
模型的三条核心特征：排斥指每个位置最多一个粒子，这条把粒子之间唯一的相互作用限制为阻断；随机指粒子是否移动
由概率决定；不对称指向前与向后的尝试概率不相等，记作 𝑃
前进
与 𝑃
后退
，两者不等就意味着系统有一个偏向，整体会出
现净流动。密度是一个派生量：𝜌=𝑁/𝐿，表示被占据的格点比例。
它模拟什么。 三处真实场景可以直接对应到这三个参数上。交通流把每个格点看成一段路、把粒子看成一辆车、把空格点
看成空出的路面：𝜌 就是车流密度，向前的偏向对应所有车朝同一个方向开，高密度下空格点稀少，粒子频繁互相阻断，
模型就会给出走走停停的拥塞。生物分子马达把格点链看成一条轨道、把粒子看成在轨道上步进的马达：马达沿轨道有方
向偏好地前进，且不能与前一个马达重叠。非平衡系统中的传输过程把格点链看成一段受驱动的通道：系统不断被驱动、
不断耗散，不会像无驱动的随机行走那样走向静止分布。ASEP 把驱动、随机、排斥三条约束装在最小的结构里却仍可解析
处理，因此是非平衡统计物理的标准范例（模型出处：Mallick, The Exclusion Process: A paradigm for non-equilibrium
behaviour, Physica A 418, 2015）。本节只把它当数据结构练习题的来源，不展开统计物理的推导与解析结果。这一步的边界
划在这里，是因为本节要练的是链表，不是物理。

表示上的三个判断（辅导分析，实现前先想清这三件事）
模型定下来之后，剩下的全部工作是表示与实现。表示上有三个判断必须先做，做错了后面改不动。
判断一：格点链，还是一串粒子记录。 两种候选都像链表。格点链是 𝐿 个节点，每个节点代表一个格点，节点内保存占据
标记（这个格点上有没有粒子、是哪一个）与后继引用；粒子链是只把被占据的格点做成节点，每个节点记一个位置，空
格点不出现在链上。判据是判空的代价：在格点链上，判空是读一个节点的标记，代价 𝑂(1)；在粒子链上，判空的含义变
成“某个位置在不在链上”，而链表上没有随机访问，只能沿链找，代价 𝑂(𝐿)。结论是取格点链：节点数恒为 𝐿，与粒子数无
关，空格点也各占一个节点，代价是每个节点多保存一个标记。粒子链在 𝜌 很小的稀疏场合能省内存，但把每一次判空都
变成一次走链，代价方向正好相反。
判断二：周期边界怎么表达。 两种候选。首尾相接是把尾节点的后继指回头节点，环在建立链表的时候一次接完，此后每
个格点的两个邻居都可以从链上直接拿到，边界不出现特例。边界处特判加取模的位置下标是每次移动都判断是否跨界，
跨界时把位置折回另一端；这条路在数组上很自然，在链表上不省任何东西，因为“取第 𝑘 个格点”本身要沿链走 𝑘 步，取
模只是把回绕写成一个算式，走的步数一步没省。结论是取首尾相接。代价必须一起讲清：接成环之后链上不再有空值，
走链不能以“遇到空值”作为终止条件，必须以格点数计数终止，计数写错就是死循环。常见的链表错误里有一类是“不小心
造成环导致遍历死循环”；这里的环是有意造的，判断它是哪一种只能靠“终止条件是什么”。
判断三：向后尝试要走几步。 向后尝试的目标格点是当前格点的前驱。两条路：走链时同时持有前驱与当前（两个变量同
步前进），一个循环里就把两个邻居都拿到了，向后尝试另付 0 次访问；反过来，每次向后尝试都从 head 重新走一遍去找
前驱，单次向后尝试的代价就从 1 次访问涨到平均 𝐿/2 次。实测（𝐿=50，𝑁=40，同一种子，只算决策那一遍走链访问
的格点数）双指针版 50 次，反例版 348 次，而这一步里只有 11 次向后尝试；粒子更多的模型按 𝑁×𝐿/2 增长，5000 步的
规模下会直接拖垮运行时间。这条判断与本讲前面删除操作的结论是同一件事：单链表上前驱只能靠走链拿到。

附录（放在正文之后）：分治、递归与循环的思维专题
正文讲链表的写法，附录把正文里反复用到的三条思维收成一般形式、判据与反例。
术语：
分治（divide and conquer，分而治之）指把规模为 𝑛 的原问题划分成若干规模更小的同类子问题，各自求解，再把子问题的
解合并回原问题的解的一套做法。
递归（recursion）指函数直接或间接调用自身的写法，它把状态保存在调用栈上。
循环（loop）也叫迭代（iteration），指用循环变量与控制条件重复执行一段代码的写法，它把状态保存在变量里。
基线（base case）指分解到此为止、可以直接求解的最小规模。
调用栈（call stack）是运行时为每个尚未返回的函数调用保存局部变量与返回位置的一块内存区域，其中一层所占的空间称
为栈帧（stack frame）。
弃（discard）指分完之后依据某种判断把一部分子问题整块排除在后续计算之外。

5.前提二，子问题相互独立：子问题之间不重叠、不互相依赖，可以各自求解。
