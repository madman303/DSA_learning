合并两条有序链表与长链三等分：分与治的两个基本操作
合并（merge）指把两条已经各自有序的链合并成一条有序链：不新建数据节点，只把原有的节点按数据大小依次接在结果
链的尾部。做法是三个指针：p 与 q 各指两条输入链的当前节点，tail 指结果链的末尾。
步骤：每轮比较 p 与 q 的数据，把较小的那一个接到 tail 之后，再把这个指针前进一步；当其中一条链走完时，停止逐节
点比较，把剩下的一整段直接接在结果链尾部。最后一步是整段相接，不是逐个节点相接，这是本题第一个要点：走完的
那条链已经有序，剩下的那一段也一定不小于已接上的全部节点。
实测（./complex_ops，两条各三个节点的链，1 -> 3 -> 5 与 2 -> 4 -> 6）：合并得到 1 -> 2 -> 3 -> 4 -> 5 -> 6，走链 10
步，改指针 8 次，比较 5 次。10 步的构成值得数一遍：5 次从输入链取节点各前进一步，5 次把结果链的尾指针前移一步，
所以每接上一个节点要走两步；5 次比较恰好是 𝑚+𝑛−1，其中 𝑚=𝑛=3，这也不是巧合：每一轮比较消耗一个节点，
最后一次比较之后剩下的一整段不需要再比。

长链三等分（split into three）指把一条长链按结点数切成三条长度大致相等的短链。在两个节点之间置 next = NULL 的位置
称为断点，三等分需要两个断点。做法是快慢指针（fast and slow pointers，两个指针同向走但每轮的步数不同，用步数比
把某个位置算出来），分两趟各定一个断点：
1.第一个断点：快指针每轮最多前进三步、慢指针每轮前进一步。快指针走到链尾时，慢指针恰好停在第 ⌈𝑛/3⌉ 个节点上，把
它当作第一段的尾，在它和下一个节点之间切断。
2.第二个断点：在余下的那一段上，快指针每轮走两步、慢指针走一步，循环在快指针前方不足两个节点时停下；停下时慢指
针恰好停在第 ⌈𝑚/2⌉ 个节点上（𝑚 是余下那一段的长度），在它和下一个节点之间切断。
两个断点的位置都由步数比算出来，因此不需要先数一遍链长，两趟走链合计 𝑂(𝑛)。取整规则用 ⌈⋅⌉：余数一律给前面那一
段。
为什么用两趟双指针，而不是一趟三个指针：一趟三指针并非不可行，难在边界。𝑛≤2 时链上的节点填不满三个非空的
段，实现必须为这些退化情形单独写守卫；失败实现（见本节详解的实测对照）只防住了“一个数据节点也没有”这一种，
𝑛=1、𝑛=2 时把同一个节点接进了多条链。而且段边界与“先接哪一段、后接哪一段”的次序，要求三个指针在全程同时
维护同一组不变式，出错面大。两趟方案每一趟只有一个不变式（快慢步数之比定出断点），第二个断点从余链的头部重新
起算，𝑛=0、1、2 各分支的判定点彼此独立、可逐个实测

交换指定节点与逆转链表：三指针的滚动与相邻情形的坑
交换两个指定节点指把链上第 𝑖 个与第 𝑗 个数据节点互换位置；位置从哑节点起算，第 0 个就是第一个数据节点。做法分
两步：先找到这两个节点的前驱（指向某个节点的那个节点），再按“相邻”与“不相邻”两种情形分别接指针。
不相邻情形改写四次：prevI 的 next 改指 nodeJ，prevJ 的 next 改指 nodeI，再把两个节点各自的 next 互换。相邻情形只有
三次，因为这时两个前驱关系重合：第 𝑗 个节点的前驱就是第 𝑖 个节点本身，于是“把 prevJ 的 next 改指 nodeI”这一步会先
把节点指回自己，必须由后面的两步覆盖回来。实测（六节点链 1 2 3 4 5 6）：

逆转链表（reverse in place）指把链上节点的次序整个倒过来，要求不新建数据节点。做法是三个指针滚动；三个指针分别
是前驱 prev（已经翻好的那一半的当前头）、当前 curr（正在处理的节点）、以及处理前先记下的后继 next：
1.先把 curr 的后继记下来（这一步不做，后面改指针就会丢掉这条链的后半段）。
2.把 curr 的 next 改指 prev，于是 curr 接进了已经翻好的那一半。
3.prev 前移到 curr，curr 前移到刚才记下的后继，进入下一轮。

4.循环结束后把哑节点的 next 接回 prev，它现在是新的第一个数据节点。
为什么赋值次序不能颠倒：每一步只有一份“后继地址”，它存在 curr->next 里；先写 curr->next = prev 就会把这份唯一的
拷贝覆盖掉，后半条链再也走不回去，结果是断链或（在交换相邻节点这类操作里）成环。实测（五节点链 1 2 3 4 5）：
逆转得到 5 4 3 2 1，走链 5 步（每个节点被访问一次）、改指针 6 次（五个节点各一次，加上哑节点接回的一次）；再逆转

检环与找环起点。 判定一条链上是否有环，用快慢指针：慢指针每轮走一步、快指针每轮走两步；若快指针先走到链尾，

链表上的冒泡、插入、归并与三路快速排序
冒泡排序在链表上有两种写法。交换节点（改指针）是链表本来的做法：比较相邻两个节点的数据，逆序时把这两个节点
整体换位，改的是三条指针。交换数据域（搬元素）是把两个节点的数据互换，节点本身不动，改的是两个位置上的值。
实测（𝑛=64）：交换节点写法比较 2679 次、改指针 3126 次；交换数据域写法比较 3276 次、搬移 3126 次。三处数字值得
逐个读：
两个 3126 是同一个数，它等于交换次数乘以三（1042×3=3126）：交换一次要么写三条指针，要么写三个位置的数据。交
换次数一样，差别只在写的是什么。
比较次数不同（2679 与 3276），原因是交换节点的写法在每次交换之后本轮会跳过一个比较对（被交换过去的那个节点要到
下一轮才与它的新邻居比较），交换数据域的写法不跳。两种写法都是同一种算法的合法落法，比较次数的差别是写法造成
的，不是算法造成的。
两行的代价合计是同一个数：交换节点写法把 3126 次全记在改指针一列，交换数据域写法把同样的 3126 次全记在搬移一列：
交换节点那一侧的元素确实一步没动，代价只是换了名字。

双链表与循环链表：多一个指针值不值
三种常见类型的定义如下。
单链表（singly linked list）：每个节点由数据域与一个指针域组成，指针域指向后继节点，只能沿一个方向走；尾节点的指
针域为空值（C 侧 NULL，Julia 侧 nothing）。
双链表（doubly linked list）：每个节点由数据域与两个指针域组成，一个指向后继节点、一个指向前驱节点（前驱指在链上
排在它前面的那个节点），因此可以朝两个方向走。它换来的是“删除一个已知节点时不必再找前驱”，代价是每个节点多一
个指针的内存，以及插入与删除时要成对维护两条指针（任一节点的 next 改了，被指向的那个节点的 prev 也要跟着改）。
循环链表（circular linked list）：让单链表的尾节点的指针域指回头节点（首尾相接，环由数据节点组成），于是任意节点都
可以当作起点，从任何一个节点出发沿着指针走都能回到原处。它适用的场景是环形遍历（走一圈回到起点，判终止用计
数而不是判空值）、周期性边界（走到一端就从另一端出现，第 3 讲 ASEP 练习里的边界正是这一条）、以及约瑟夫问题这
类围成圈逐个出列的过程。

静态链表（选读）：用数组兼顾两者的优点
第 3 讲课下练习的第四题问的是：是否可能把链表与一维数组的优点结合起来。当时的答案只要求给出猜想与一处困难。
先把两边的优点列清楚。数组的优点来自连续存储：按序号访问是一次地址运算（𝑂(1)），没有额外的结构开销。链表的优
点来自指针：插入与删除只改指针、不搬元素，重排或排序时不必移动数据本身。两者的困难也清楚：数组一次下标运算
就能定位，可一旦要重排就得搬元素，元素越大搬得越贵；链表不搬元素，可定位只能走链。
静态链表（static linked list，也叫游标链表 cursor-based linked list）把两者的优点摆在一起：数据放进一个数组（内存一次
分配完），次序放进一个下标数组，用下标代替指针。落地写法是两个数组加一条空闲链：
数据数组 data[i]：存第 𝑖 个槽位的数据。
下标数组 next[i]：存第 𝑖 个槽位的后继槽位下标，−1 表示没有后继。
空闲链：所有空闲槽位用下标串成一条链，free 是它的头。申请一个槽位就是取空闲链的头，释放一个槽位就是把它挂回空
闲链。
这套写法的关键是：链的形状完全由下标数组给出，与数据在数组里的物理次序无关。重排、排序、按新次序遍历都只改
下标数组，数据数组一个位置都不动。
若把结构写成三个数组（数据、下一个、位置），后两个数组的职责会重叠；按“下标模拟指针”的实际做法，两个数组加一
条空闲链就够了，第三个数组在这里是冗余的。

工程实战：C 项目组织与函数库
前几节的链表代码已经攒下不少：第 3 讲的建链、插入、删除与遍历，本讲的合并、拆分、逆转与检环，再加上链表上的
四种排序。这些函数眼下散在各个示例脚本里，一个脚本一份主函数，改一处就要把整份脚本重编一遍。一个真正的 C 项
目要把三件事的边界立清楚：对外承诺写在头文件里，实现在源文件里，测试单独放在测试目录里；再把一批函数装成一
个动态链接库，让调用方不必知道实现也能用它们。
四个术语定义如下。编译指把 C 源文件翻译成机器码的过程。目标文件（后缀 .o）是编译的中间产物，里面是机器码与一
张符号表，各符号的最终地址还没有确定。链接指把若干目标文件与用到的库拼在一起、确定各符号的地址、产出一个可
执行文件或一个库的过程。动态链接库（后缀 .so）是一种在程序运行时才被加载的库：库的机器码不复制进可执行文件，
可执行文件里只留一份引用，程序启动时由加载器把库装进内存并解析符号；同一份库文件能被多个程序共用，改库之后
不必重编用它的程序。
头文件（后缀 .h）写一个模块对外的承诺，即类型定义与函数声明，供别的模块包含；源文件（后缀 .c）写这个模块的实
现，别人不必读它。
Makefile 是一份用构建规则写成的说明文件。每条规则写清三样东西：目标（要产出的文件）、依赖（产出它需要的输
入）、命令（产出它的动作）。make 读这份文件，比较目标与依赖的时间戳，只重做那些依赖比目标新的部分，所以改了
sort.c 只会重编排序那一块，不会把整个项目重来一遍。
项目里每一件东西都有它的位置，目录长这样。
顶层的 Makefile：先出动态链接库，再出调用这个库的测试程序；另备 run 与 clean 两个快捷目标。
README.md：写目录结构、编译与运行方法、模块与文件的对应关系。别人照着它能把项目跑起来。

标准库的调度层与算法内核
标准库是一门语言随发行版一起提供的那一套基础函数与类型的集合，它是这门语言里被读得最多、也被改得最多的代码。
读标准库代码对掌握一门语言见效快，收获有四条。
1.学到语言的最佳实践与规范写法。标准库里的命名、参数次序、错误处理方式就是这门语言的惯例，照它写，代码从第一天
起就像这门语言的本地写法。
2.理解底层实现与设计思路。同一件事在标准库里往往有几条实现路径，把路径挑出来的依据（数据规模、元素类型、是否需
要稳定排序）看明白，抽象能力跟着长。
3.提高编程能力与代码质量。标准库里那些反复出现的写法（提前返回、边界检查、把公共部分抽成小函数）是现成的模板，
照着用能避开常见错误。
4.掌握高级技巧与优化方法。为了把常数压下来，标准库里用了一些单独讲要花很多篇幅的手法，读到之后，视野与工具箱同
时变宽。
标准库里的代码不总是短。把一件简单的事写长的原因，正是阅读时要找的东西。调度指按输入的类型、长度、比较函数
等条件把一次调用分派到不同实现的那一层代码，它不改变任何结果，只决定走哪条路。标准库里大量篇幅花在调度与辅
助函数上，真正的算法内核只占少数几处。

Lisp 与 Scheme 的渊源
nil 与 cons 这两个名字来自 Lisp 与 Scheme 语言。cons 是这两个语言里最基本的构造子，把两个对象接成一个有序对；nil
是空列表的名字。一串 cons 嵌套起来就得到一张列表，一张列表的存储方式与链表完全一致。
渊源可以从两条线看。
列表到 LISP 到 lambda 演算到数学。列表是最基础的数据结构之一，20 世纪 50 年代的 LISP 语言把它当作核心：LISP 的核
心数据结构就是链表，一切复杂结构都能用链表与递归表达。LISP 的设计直接受到 lambda 演算（一种用函数与函数应用表
达计算的形式系统，是函数式编程的理论基础）的影响，于是链表与递归把数学上的函数与数据结构直接带进了程序，LISP
因此得了“计算机科学中的数学”这个位置。
LISP 到 Scheme 到计算机科学。LISP 之后，Scheme 一类语言把函数式思想推进了一步，强调代码即数据，支持高阶函数
（把函数当作参数传入或当作结果返回的函数）与闭包（带着自己定义时环境的一段可调用的代码）。Scheme 与它的教材成为
一些高校计算机入门课的标准教材，训练出来的是用数学的方式想程序的人。
这两条线解释了一件在本课反复出现的事：链表与递归总是同时出现。链表的定义本身就是递归的，一张链表要么是空表，
要么是一个节点接一张链表；用递归写链表上的操作，代码与定义同形，正确性也由定义直接给出。第 3 讲 Julia 那一节里
的两个类型 Cons 与 Nil，正是这套记法在 Julia 里的落地：非空链记作 Cons，空链记作 Nil，一个抽象类型下面挂两个具体
类型，操作按分派落到该去的那一支。看到 Julia 侧的 Cons 与 Nil 时认出它们的来历。

两语言问题与本课的分工
两语言问题指高性能计算里长期存在的一种两难，三条表述合起来就是它的全貌。
1.用编译语言写代码慢：C 这一类语言的性能好，但写起来要管的细节多，从想法到能跑的代码距离长。
2.用解释语言跑起来慢：一类脚本语言的写法轻快，但运行时的开销大，把算法改成能用的性能往往要再走一遍别的语言。
3.在两种语言之间来回搬运也慢：一部分写在快的语言里、一部分写在快的语言写的库里，拼接处的边界与数据转换既费时间
又容易引入错误，调起来还要两套工具。
Julia 试图同时解决这三件事：用接近脚本语言的写法，拿到接近编译语言的运行速度，靠的是把类型信息带进编译期。两
种语言各有它负责看清的东西。
C 负责看清内存与指针：节点在哪里、谁申请、谁归还、空值是谁的约定、指针赋值顺序错了会断链还是成环。C 把地址与
生命周期摆在台面上，链表的存储结构在 C 侧是看得见摸得着的。
Julia 负责看清类型与抽象：一个结构可以由抽象类型加若干具体类型组成、空值写进字段类型、操作靠分派落到正确的实
现。链表“次序由指针给出”这条结论在 Julia 侧表现为“次序由引用与类型给出”，反过来照出前一条的边界在哪里。
复杂度与性能的提示不在本节展开：链表查找做不到 𝑂(log𝑁)，因为链表没有随机访问，连“取中点”这一步本身都是 𝑂(𝑛)，
这件事第 3 讲的附录已经讲过。
三件课外的完成标准：读标准库那一件落成一份阅读报告；Lisp 与 Scheme 那一件落成一次能说清来龙去脉的复述；两语言
的分工那一件落成写代码时的一个自觉，即每写一处链表操作，知道自己在看的是内存还是类型。

Gantt 图（甘特图）是一种横向条形图：用一根从左到右推进的时间轴承载若干任务，每个任务占一根横条，横条的左右
两端是任务的开始与结束时刻，横条上按完成比例填充的部分给出进度，任务之间的先后约束用连接条或箭头画出。七个
术语在这里给出完整定义（术语对照表中另含总名 Gantt 图与派生量工期两项）。
任务（task）：一件有明确目标、可以独立安排与跟踪的工作单元。在 Gantt 图里它占一根横条；在数据上它通常带一个标
识、一个名称与一段起止时间。
步骤（step）：任务内部按顺序执行的一个动作。一个任务由一串有序的步骤组成，步骤之间的先后是执行次序，不是依赖里
那种可以并行、可以交叉的约束。
时间轴（timeline）：图下方从左到右推进的时间刻度。横条的左右两端直接落在刻度上，读图时先看刻度再看横条。
条形（bar）：图中代表一个任务的那根横条。它的左端对应该任务的开始时刻，右端对应结束时刻，长度对应该任务的工期，
即起止时刻之间的时间长度。
进度（progress）：横条上按完成比例填充的那一部分，回答这项任务做到哪一步了。填充比例与横条长度是两个不同的量：
长度是计划的时间跨度，填充是实际推进的程度。
依赖（dependency）：两个任务之间的先后约束，在图上用连接条或箭头表示，含义是前一个任务不结束，后一个任务不能开
始。
工期与进度之外，图上还可能出现里程碑（milestone）：一个只有时刻、没有时长的检查点，通常画成一个菱形或一根零宽度
的标记，用来说明某件事必须在某个时刻之前完成。

Gantt 图的用处、优点与局限
Gantt 图能回答的问题可以归成六类。
1.哪些任务要做：纵轴那一列就是答案，图上没有的任务不在计划里。
2.各在什么时候做：每根横条的位置就是各自的开始与结束时刻。
3.哪些任务可以并行：时间区间重合、并排出现的横条就是可以同时做的那几件。
4.整件事还要多久：最后一根横条的右端离现在有多远，就是计划上的剩余时间。
5.哪些任务卡住了后续：被连接条指着的那几个任务，只要它们没结束，后面的就动不了。
6.眼下进度落后多少：把每根横条的填充位置与时间轴上“今天”这一根竖线对照，落后与提前一眼可见。
项目管理里用它做四件事：排计划，把任务摊到时间轴上，先定次序再定时刻；对齐分工，同一张图上看清谁在什么时候
忙、谁在什么时候空；跟踪进度，横条的填充随实际推进更新；向上汇报，一张图代替一段文字说明。
它的四条优点：
1.直观：时间占用与先后关系变成位置与长度，不依赖文字描述就能读懂，读图的门槛几乎为零。
2.沟通成本低：同一张图可以给不同角色看，讨论与修改围绕同一份图形进行，不必各自在脑子里重建一份计划。
3.与日历对齐：横条直接落在日期刻度上，排期与周次、节假日、课程安排这类真实的时间边界自然对上。
4.计划与实际可以放在一处对照：计划条与实际条并排画，落后与提前在图上是一条缝隙的宽窄，不需要再去比对两份表。

时间相洽性检查：本课的判定规则
相洽指同一串步骤内部在时间上说得通，不存在自相矛盾的时间。它至少包含两层：一是单步自身开始与结束的关系，二
是同一串步骤内两步之间的关系。两层之上还有一条前提，即哪些步骤参与检查、哪些不参与。
本课的时间约定：一个步骤占用的时刻记成一个半开区间 [start, end)，其中 end 是这一步不占用的时刻。也就是说，这一
步占用的时刻是 start 到 end 之间不含 end 的那些时刻。取半开区间有一个直接好处：前一步的结束时刻本身不占用时间，
后一步可以从这个时刻开始，两步既不重叠也不留缝。这条约定由本课定。
三条可执行条件。
1.自身相洽：起止都存在时要求 start ≤ end。start 晚于 end 为不相洽，须报错。这条条件管的是单步自身，与别的步骤无
关。
2.零时长：start 等于 end 表示零时长的步骤，它占用的时刻为空，是一个空区间。本课按空区间处理并允许存在，例如只需
记录一个时刻的检查点。空区间与任何步骤都不冲突。
3.两步重叠：把两步记为 [s_i, e_i) 与 [s_j, e_j)，两步重叠当且仅当 s_i < e_j 且 s_j < e_i。重叠即相洽性冲突，重叠区
间是 [max(s_i, s_j), min(e_i, e_j))。
第 3 条有一处前提必须写明：它只在两步都已排期、且两步的区间都非空时成立。空区间里一个时刻都没有，它与任何步
骤都不冲突；若把空区间直接套进重叠公式，位于另一个步骤区间内部的零时长步骤会被判成重叠，这是一个真会发生的
错判。
未排期的步骤不参与检查：起止时间缺省的步骤跳过重叠判定，既不报冲突也不报错；只给一端时间的情形按未排期处理，
同样跳过。
必须区分的六种情形。
