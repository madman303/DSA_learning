案例二：人际相似度度量
背景介绍：在现代社会，推荐系统无处不在，电商平台为你推荐商品，社交网络为你推荐好友，招聘网站为你推荐职位。
这些系统的核心问题之一，就是如何衡量“人与人之间的相似度”。 - 推荐系统背后的本质问题：如何定义两个人之间的“距
离”？距离越近，推荐的相关性越高。
最初的思路：可以用空间位置（如地理坐标）来衡量距离。例如，住得近的同学可能更容易成为朋友。

更复杂的情况：政治信念、价值观等深层次特征，也会影响人与人之间的距离，但这些特征往往难以量化。

C 语言的基石：直接内存抽象
指针：
指针是C 语言的灵魂。每个变量在内存中都有一个地址，
指针就是用来存储这个地址的变量。
通过*（解引用）和&（取地址）操作符，程序员可以直接
访问和操作内存中的数据。
数组：
数组在C 中是一块连续的内存区域，元素类型相同，便于
高效访问和遍历。
数组名本质上是指向首元素的指针，但数组和指针并不完
全等价（如sizeof、内存分配等）。
结构体：
结构体（struct）允许将不同类型的数据聚合在一起，形
成自定义的数据类型。
结构体的每个成员在内存中有固定的偏移量，便于整体管
理和操作。
核心思想：
C 语言让程序员直接管理内存，带来极高的性能和灵活性，
但也要求开发者对内存分配、释放、越界等问题高度负责。

Julia 的平衡：性能与抽象的双赢
类型系统：
Julia 支持强类型和类型注解，允许开发者为变量、函数参
数、返回值指定类型。
类型注解有助于JIT（即时编译）优化，提高代码运行效率。
数组：
Julia 的数组是可变的、类型化的、连续的内存块，底层实
现与C 类似，支持高效的数值计算。
支持多维数组，且索引从1 开始。
结构体：
struct 定义不可变类型，mutable struct 定义可变类型。
不可变类型适合做数据快照、哈希表键等；可变类型适合
需要频繁修改的场景。
内存与性能：
Julia 通过类型推断和JIT 编译，实现了接近C 的性能，同
时保留了高级语言的易用性和灵活性。
合理使用类型注解和数据结构，可以极大提升代码效率。

引用与指针的关联与区别
相同点：
都是“间接访问”数据的机制，不直接存储数据本身，而是指向（或引用）数据在内存中的位置。
允许多个变量指向同一份数据，实现数据共享。
区别：
C 语言的指针是内存地址的直接操作，支持算术运算（如p+1），可以指向任意类型的数据，甚至可以指向指针本身（多级指
针）。
引用（Reference）（如Python、Julia、Java 等）是更高级的抽象，通常不允许直接操作内存地址，也不支持指针算术。引用本
身不可更改为指向其他对象（如C++引用），但Python/Julia 的变量可以重新绑定。
指针需要手动管理内存（分配、释放），引用通常由语言自动管理内存（垃圾回收）。
Python
对于不可变对象（如int），变量重新赋值会指向新对象，原对象不变。
对于可变对象（如list），多个变量指向同一对象，修改会影响所有引用。
Julia1
Julia 变量本质上也是“绑定”到对象的引用，和Python 类似。
不可变对象赋值不会影响原对象；可变对象的修改会影响所有引用。

请大家打开自己熟悉的AI 助手（如ChatGPT、Copilot、DeepSeek 等）。

C 语言：使用 clock() 计时
C 语言提供 <time.h> 头文件中的 clock() 函数，用于测量程序运行的CPU 时间。
基本用法：在代码片段前后分别调用 clock()，计算差值并除以 CLOCKS_PER_SEC 得到秒数。

#include <iostream>
#include <chrono>
int main() {
// 获取起始时间点
auto start = std::chrono::high_resolution_clock::now();

// 需要计时的代码
long long sum = 0;
for (int i = 0; i < 1000000; ++i) sum += i;

// 获取结束时间点
auto end = std::chrono::high_resolution_clock::now();

// 计算耗时（单位：微秒）
auto duration = std::chrono::duration_cast<std::chrono::microseconds>(end - start);
std::cout << "运行时间: " << duration.count() << " 微秒" << std::endl;
return 0;
}
chrono 支持多种时间单位（秒、毫秒、微秒、纳秒等），可根据需求灵活选择。

什么是指针
指针是一种特殊的变量：它所存储的数值不是“数据本身”，而
是一个内存地址。
普通变量：保存数据本身。
指针变量：保存某个数据的地址。
指针具有双重性：它既是一个“值”（地址），也是对另一对象
的“引用”。
int x = 10;
int *p = &x;
printf("x 的值: %d\n", x);
printf("p 存储的地址: %p\n", (void*)p);
printf("通过 p 访问的值: %d\n", *p);
图 1: 指针的双重性：指针变量 p 存储地址 0x1004，通过
解引用指向对象 x
指针 p 自身也占据一块内存。
指针的“步长”由所指类型的大小决定：p+1 前进
sizeof(*p) 字节。
指针本身的大小由平台决定（64 位平台常为 8 字节），
与所指类型无关。

lvalue 与 rvalue
lvalue（左值）：表示一个可寻址的内存位置，有地址，可出现在赋值语句左边。
rvalue（右值）：表示一个具体的数值或临时结果，没有固定地址，只能参与计算。
指针的双重性在此体现得尤为明显：
int x = 5;
int *p = &x;
*p = 20; // *p 作为左值，修改 x
int y = *p + 1; // *p 作为右值，提供 x 的值参与运算
如果 p 指向无效地址（未初始化或悬空），那么 *p 无论作为左值还是右值，都会导致程序崩溃。

指针算术
指针不仅可以存储地址，还能进行算术运算：
p++：指针向后移动一个元素。
p+n：指针向后移动 n 个元素。
p1 - p2：计算两个指针之间的距离（元素个数），结果类型
为 ptrdiff_t。
指针算术的步长不是字节，而是指针所指类型的大小。
int arr[5] = {10, 20, 30, 40, 50};
int *p = arr;
for (int i = 0; i < 5; i++) {
printf("%d\n", *(p+i)); // 等价于 arr[i]
}
合法性与边界
p1 - p2 只有在两个指针指向同一个数组（或末端后一
位）时才有定义。
指针算术仅在同一数组内合法，越界是未定义行为。
允许计算“末端后一位”（如 arr + n），常用于迭代结束
判断，但不能解引用它。

动态内存：为什么需要
栈区、堆区、数据区、代码区
栈区：局部变量与调用帧，随作用域自动释放。
堆区：运行时动态分配，由程序员用 malloc/calloc/
realloc/free 管理。
数据区：全局/静态变量（含 BSS 未初始化区）。
代码区：只读指令区域。

为什么需要动态内存
数据规模不确定：输入文件大小、网络包数量等只有运
行时才知道。
生命周期跨越作用域：函数返回后仍需存活的数据无法
用栈变量安全承载。
大对象与灵活结构：链表、树、图、可扩容容器需要分

堆：手动管理、容量取决于进程可用内存，适合大对象

typedef struct { int *data; int size; int capacity; } DynamicArray;
static int ensure_capacity(DynamicArray *da, int need) {
if (need <= da->capacity) return 1;
int newcap = da->capacity ? da->capacity : 2;
while (newcap < need) newcap *= 2;
int *tmp = (int*)realloc(da->data, (size_t)newcap * sizeof(int));
if (!tmp) return 0; // 失败：保留旧内存与旧指针
da->data = tmp; da->capacity = newcap; return 1;
}
static void push_back(DynamicArray *da, int v) {
if (!ensure_capacity(da, da->size + 1)) fprintf(stderr, "realloc 失败\n"); exit(1);
da->data[da->size++] = v;
}

安全与常见错误
警惕 1：指针与动态内存的常见陷阱
分配返回值未检查：所有 malloc/calloc/realloc 必须判空，失败立即返回或进入统一清理路径。
未初始化使用：malloc 后立即显式初始化，或改用 calloc。
悬空指针：free 后继续读写、返回栈上地址。规避：free(p); p = NULL;，不返回局部对象地址。
内存泄漏：丢失最后一个可达指针（被覆盖、异常路径、提前返回）。规避：分配附近就写出对应 free()。
二次释放：统一所有权归属，仅“唯一所有者”负责释放，释放后立即置空。
越界访问：封装容量与长度抽象（如 DynamicArray），所有写入前做边界检查。
realloc 误用：直接 arr = realloc(arr, new_size) 会在失败时丢失原指针。总用临时指针接收返回值。
