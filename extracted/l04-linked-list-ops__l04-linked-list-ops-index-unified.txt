# 合并：三个引用，剩下的一整段一次接上
function merge_sorted(a::Node, b::Node)
res = new_sentinel()
tail = res
p = a.next
q = b.next
while p !== nothing && q !== nothing
CMP[] += 1
if p.data <= q.data
set_next(tail, p)
p = advance(p)
else
set_next(tail, q)
q = advance(q)
end
tail = advance(tail)
end
set_next(tail, p !== nothing ? p : q)
set_next(a, nothing)
set_next(b, nothing)
return res
end
# 三等分：第一个断点按 3:1，第二个断点在余下部分按 2:1
function split_three(head::Node)
t1 = head
fast = head.next
while fast !== nothing # 快指针最多三步，慢指针一步
k = 0
while k < 3 && fast !== nothing
fast = advance(fast)
k += 1
end
t1 = advance(t1)
end
s2 = t1.next
set_next(t1, nothing) # 第一个断点
if s2 === nothing
return (head, new_sentinel(), new_sentinel())
end
t2 = s2
f2 = s2
while f2 !== nothing && f2.next !== nothing && f2.next.next !== nothing
f2 = advance(advance(f2)) # 快指针两步
t2 = advance(t2) # 慢指针一步
end
s3 = t2.next
set_next(t2, nothing) # 第二个断点
p2 = new_sentinel(); set_next(p2, s2)
p3 = new_sentinel(); set_next(p3, s3)
return (head, p2, p3)
end

1.空链参与合并：不能对空链的哑节点之后解引用，两题的入口都要先判 head->next == NULL 一类的情形。
2.只有一条链有节点：另一条链走完的判定要在循环条件里一次写完，不要在两处分别处理。
3.合并结束后输入链的哑节点必须与新链脱开，否则同一个悬空指针会被释放两次。

static void reverseList(Node *head) {
Node *prev = NULL;
Node *curr = head->next;
while (curr != NULL) {
Node *next = advanceNode(curr); // 先把后继记下来
setNext(curr, prev); // 再改当前节点的指针
prev = curr;
curr = next;
}
setNext(head, prev); // 把哑节点接回新的第一个数据节点
}

三个追问的参考回答：
1.函数逻辑：逆转函数把链分成“已翻好的前缀”与“还没处理的后缀”，每轮把后缀的第一个节点摘下来接到前缀的最前面；curr-
>next = prev 这一步就是“摘下来接上”，它必须发生在记下后继之后。
2.如何不丢节点：每一轮进入循环时，后继地址只存在 curr->next 这一份拷贝里；先把它取到 next 变量里，再改 curr->next，节点
就不会丢。丢节点的后果分两种：后半段还在内存里但走不到（断链），或者某个节点被指了两次而形成环。
3.调用后头节点怎样：函数把哑节点的 next 重新接到新的第一个数据节点上，因此调用方持有的头节点（哑节点）本身没变，不
需要接收返回值；如果实现成“把新的头节点返回给调用方”，调用处就要把返回值重新赋回去，两种约定不能混用。这也解释
了为什么本题的形参是头节点本身而不是指向头指针的指针。
另一种常见写法的实测：另一种交换函数不分相邻与不相邻，一个函数处理两种情形。在一到六号位置的全部 30 组有序组
合上跑，与“把第 𝑖 与第 𝑗 个位置上的数据互换”的期望结果逐组一致，说明这套写法的三次赋值在相邻时正好互相抵消。

}
对比两段可以看到双链表省掉的是那一圈走链，付出的是一次成对维护（两条指针）：删尾那条分支里，prev 指针的维护同时
承担了“新尾节点是谁”的信息，这也是双链表结构里“尾指针与 prev 指针互为冗余”的一处体现。
约瑟夫问题的实现要点（examples/variants.c 的 josephus）：环里不放哑节点，圈由数据节点首尾相接组成；维护 prev 与 curr 两个
指针，报数 𝑘−1 次后把 curr 出列（prev->next = curr->next），计数减一；𝑛=7、𝑘=3 的出列顺序是 3 6 2 7 5 1 4，走链 14 步、
改指针 7 次。

详解 11
从抽象三数组到 C 落地写法的映射、动机展开，以及插入与删除的实测细节
动机展开三问。
1.为什么会出现静态链表：链表的两条优点（插入删除改指针、元素不动）都要靠指针，而指针对应的“按需申请”能力（malloc）
并不是随处都有。内核的一部分代码不能随便分配内存，实时系统要求分配时间是常数，程序启动早期堆还没建好，这些场
合里“节点”只能来自一块事先定好的数组。静态链表就是在这种约束下把链表做出来的做法。
2.没有动态分配时怎么办：把“申请”与“释放”这两个动作改成对空闲链的两次下标改写。申请一个槽位是从空闲链头取下一个；
释放一个槽位是把它挂回空闲链头。两个动作都是 𝑂(1)、都是常数时间，且不产生内存碎片，因为整个数组一次分配。
3.为什么避免搬移大对象：数组上重排元素要按字节搬，元素越大越贵；而重排的目的通常只是“换个次序”。“换个次序”这件事
只需要改变读取的顺序，不需要改数据的位置。把次序放进下标数组之后，重排就变成了“重写下标数组”，代价只与元素个数
有关，与元素大小无关。本节实测的那份对照（512 字节对 60 字节）就是这条动机的量化结果。

详解 19
三条可执行条件的推导与六种情形的实测对照
条件一为什么是 start ≤ end 而不是 start < end。如果要求 start < end，零时长的步骤就被一律禁止，可现实中“只需记录一个时
刻”的步骤是存在的，例如一个只标记某个时刻已经到达的检查点。所以自身相洽的下界放宽到 ≤：既不合理的 start > end 报
错，又允许零时长的步骤存在，再由条件二给零时长一个明确的语义。
条件二的语义。零时长的步骤占用的时刻集合是空的。空集合与任何集合的交集都是空，所以它与任何步骤都不冲突，也不
该被当成零时刻。把零时长的步骤当成“占用了 start 这一个时刻”会引出两条错误结论：与它同时刻开始的步骤被判成重叠；
与它同时刻结束的步骤也被判成重叠。
条件三的推导。两个半开区间 [s_i, e_i) 与 [s_j, e_j) 有公共时刻，当且仅当存在一个时刻 𝑡 同时满足 s_i ≤ t < e_i 与 s_j ≤ t <
e_j。这样的 𝑡 存在，等价于 max(s_i, s_j) < min(e_i, e_j)，把两条不等式拆开就是 s_i < e_j 且 s_j < e_i。反过来，若两个条件有
一个不成立，例如 e_j ≤ s_i，则第 j 个步骤在 i 开始之前就已经结束，两步不重叠。重叠区间就是 [max(s_i, s_j), min(e_i, e_j))，
两条不等式同时成立时它的左端小于右端，区间非空。
